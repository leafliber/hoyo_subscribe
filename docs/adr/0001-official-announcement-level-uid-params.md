# ADR-0001：公告 API 采集使用登出态 `uid` 与 `level` 内容门控参数

- **状态**：已接受
- **日期**：2026-09-22
- **提出者**：P0-02 执行者（发现并申报）；验收方提请所有者裁决
- **需要所有者批准**：是 —— **已批准**（所有者 2026-09-22 明确同意"通过官方公告 webview 登出态自带的值"）

## 背景

P0-01 的可达性探针显示，主方案 §3.1 登记的三个公告接口线索虽返回 HTTP 200，业务码却是
`retcode: -1003「提交参数有误」`——一条真实数据都拿不到（`docs/evidence/p0/sources-reachability-20260921T165432Z.json`）。

P0-02 在补齐最小参数集后发现，官方公告接口还存在**按玩家等级的内容门控**
（`docs/evidence/p0/source-params.md` §1）：

| 来源 | 不带 `level` / `uid` | 带 `level` + 登出态 `uid` |
| --- | --- | --- |
| genshin-ann | total 4 | **total 41**（level=60） |
| hsr-ann | total 2 | **total 14**（level=70） |
| zzz-ann | total 3 | **total 18**（level=60） |

采集使用的 `uid=100000000` 是官方公告 webview 在**未登录状态下自带**的哑值，
`level` 为该游戏满级。两者都是**查询参数**，不是凭据。

## 受影响的合同

**本 ADR 不改动任何合同条款。**它记录的是 §3.1「参数、发布者 UID、栏目、区域与分页由 P0 保存
真实样本后登记」这一授权范围内的一次参数选择，因其涉及判断而单独留痕。

| 文档 | 章节 | 关系 |
| --- | --- | --- |
| 主方案 v2.1 | §3.1 来源适配 | 本决策是该节要求的"登记"动作的产物，未改变该节 |
| AGENTS.md | 规则 6（不绕过官方访问控制） | 本决策须证明未触碰该规则，见下 |

## 决策

三个公告来源的采集参数集**包含 `level`（满级）与登出态 `uid=100000000`**，
以 `fixtures/sources/registry.draft.json` 登记的值为准。适配器（P3-01）沿用该参数集，不自行调整。

## 为什么这不是"绕过访问控制"

AGENTS.md 规则 6 与 §3.1 禁止的是**绕过鉴权、验证码或访问限制**。本决策与之的分界：

| 判据 | 本决策 |
| --- | --- |
| 是否提交凭据（cookie / token / 签名） | **否**。请求无任何凭据 |
| 是否伪造已认证身份 | **否**。`uid=100000000` 是官方页面登出态自带值，不对应任何真实账号 |
| 接口是否要求认证 | **否**。返回 200 与完整数据，无 401/403 |
| 是否规避了拒绝信号 | **否**。没有任何请求被拒绝后改参重试 |

**对照组**：同一张卡里，米游社 `getPostFull` 返回 **403**——那是访问控制信号，执行者按规则停手，
把来源降级登记为 `maintenance-required-list-only`，未试 UA 伪装、未换 SSR 页面、未用第三方聚合后端
（`source-params.md` §3）。两者的处置差异正是本项目对这条边界的实际执行标准。

## 价值

不带这两个参数，三个游戏合计只能看到 **9 条**公告；带上后是 **73 条**。
9 条覆盖不了首版承诺的前瞻、维护、限时活动、卡池四个类别——**产品的核心内容范围直接不成立**。

## 成本

- 采集到的是满级视角的公告全集，**可能包含低等级玩家在游戏内看不到的条目**。
- 首版 `SUPPORTED_SCOPE` 不含玩家等级维度，因此这些条目会无差别地进入所有用户的日历与提醒范围。
  这是**已知且接受**的取舍：本产品是官方日程聚合，不是个人化的游戏内公告镜像。

## 安全影响

不新增攻击路径：无凭据、无会话、无授权范围变化、不引入存在性差异。
本决策**扩大的是采集面，不是权限面**。

## 预算与容量影响

条目数从 9 升到 73（约 8 倍），影响两处，均在现有参数内：

- **模型预算**：单篇抽取费用 × 篇数上升。`AI_SOFT_DAY` / `AI_HARD_DAY` 的软硬线机制本身能兜住
  （超线即降级到规则与人工路径），但 P0-03 测定单篇费用时**必须按 73 条的量级估算日消耗**，
  并与 `docs/ENGINEERING.md` §4.1 的成本护栏（不超出 Workers Paid 套餐）一起校验。
- **正文体积**：`getAnnContent` 单次返回全部正文，实测约 254 KiB。与 `SOURCE_POLL = 1,800 秒`
  相乘后的日流量已登记在 `registry.draft.json` 的 `limit_profile_measured`。

附录 A.5 的等式**不受影响**，无需重算。

## 回退

改 `fixtures/sources/registry.draft.json` 里三个来源的参数集，去掉 `level` 与 `uid` 即可，
无数据迁移成本。**但回退等于把内容范围压回 9 条**，届时需要同步收窄对外承诺的内容类别。

已发布数据的不可逆性：本决策在 P3 发布前生效，**尚无已发出的 UID、邮件或日历副本**，
现在回退没有外部残留。P3 上线后再回退，则已进入用户日历的条目会按完整快照语义被删除——
那时应走"事实撤回"路径（`retracted`，§3.3），不能当成普通筛选变更。

## 备选方案

| 方案 | 为何未采用 |
| --- | --- |
| 不带 `level`/`uid`，只收 9 条 | 内容范围不成立（见"价值"） |
| 带 `level` 但取较低值（如 1） | 门控是阶梯式的，低等级仍会漏掉大量限时活动与卡池；且"取哪一级"本身没有官方依据，比取满级更武断 |
| 改用米游社资讯作为主来源 | 其正文通道 403，只能拿到标题/图片级信息，无法支撑时间抽取 |
| 用第三方聚合后端 | §3.1 明确禁止：第三方聚合后端不能冒充官方来源 |

## 待确认

1. **P0-03 必须按 73 条量级重估模型日消耗**，并对照 §4.1 成本护栏确认 `AI_HARD_DAY` 不出套餐。
2. 目标 Cloudflare 环境用同一参数集复测可达性（§2.4 要求 E3；本卡证据为本机网络 E2 级）。
3. 若未来官方调整门控行为（参数失效或返回结构变化），按 §3.1 停用并进入维护状态，
   **不得靠试参数矩阵恢复**——那会越过本 ADR 划定的边界。
