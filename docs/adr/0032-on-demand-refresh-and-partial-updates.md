# ADR-0032：按需刷新与局部更新——站内切换复用公开副本、条件请求核对、切换筛选不退回骨架

- **状态**：已接受（所有者 2026-10-07 提出）
- **日期**：2026-10-07
- **提出者**：所有者。原话："切换页面都要重新刷新并获取信息，页面也会有闪烁，请帮我更改该模式，改为按需刷新，局部刷新，尽可能减少请求次数，且页面显示尽可能无闪烁或者大片重载"。
- **需要所有者批准**：是，已由所有者提出。修订 ADR-0015 第 8 条"每次打开都取最新"（只对同一标签页里的站内切换）；新增参数 `CLIENT_RECHECK_INTERVAL` 与 1 条启动等式。不涉及收费、供应商、权限或迁移。

## 背景

2026-10-07 按代码与本地 e2e（合成数据）核对：

- 站点是多页静态站（Astro），每次站内切换都是整页加载。公开读取按 ADR-0015 为 `Cache-Control: no-cache` 且没有校验器（ETag），浏览器无法做条件请求，每打开一页都完整下载一遍：首页 4 个接口（目录、日程各页、状态、兑换码），详情页 1 个，状态页 1 个。
- 首页切换游戏或时间范围时，`ScheduleLoader.start` 清空已显示的列表、退回骨架，并把目录、状态、兑换码连同日程一起重读（4 个请求；这三项与筛选无关）。
- 订阅页的日历卡片、浏览器通知卡片与"选择接收方式"引导各自读一次 `/api/v2/status`。
- 页头账号入口每一页都先显示「登录」，再读一次 `/api/v2/me`，确认后变成「账号」，已登录用户每次切换页面都能看到这一下跳变。
- 状态页刷新时先清空全部内容，读完再出现。

## 受影响的合同

| 文档 | 章节 | 现有规定 | 本 ADR |
| --- | --- | --- | --- |
| ADR-0015 | 决策 8 | 公开读取 `no-cache`，"浏览器每次打开都向源站取最新" | HTTP 仍是 `no-cache`；另加弱 ETag，带回一致的 `If-None-Match` 时回 304。页面在**同一标签页**站内切换、返回时复用上次核对过的副本，超过 `CLIENT_RECHECK_INTERVAL` 才用条件请求核对；刷新按钮、浏览器刷新、新开标签页仍立即向源站核对 |
| 前端 | §4.5 数据状态 | 公共旧缓存可以继续展示，但必须标明离线/陈旧及实际时间 | 不变。复用的副本带着最近一次核对的时间（304 时改写 `cache.generatedAt` 为核对时刻）；过了 `PUBLIC_CACHE_FRESH` 照旧显示"内容可能已过时"与刷新按钮 |
| 前端 | §12.3 缓存、安全与性能 | Service Worker 仅缓存白名单公开资源；私人 API 不进缓存；性能验收记录请求次数 | 不引入 Service Worker。页面副本只存公开接口响应，放在本标签页的 `sessionStorage`（关标签页即清空、不跨标签页）；私人接口不经过它。请求次数见"价值" |
| 主方案 | 附录 A.3 | — | 新增 `CLIENT_RECHECK_INTERVAL` = 300 秒 |
| 主方案 | 附录 A.5 | — | 新增等式 `client-recheck-below-public-fresh`：`0 < CLIENT_RECHECK_INTERVAL < PUBLIC_CACHE_FRESH` |

发布、日历、通知与公开接口的正文都不变；Feed 自己的 ETag 与 304（主方案 §6.6）不变。

## 决策

1. **服务端：公开读取加弱 ETag**（`apps/worker/src/public/conditional.ts`）。
   - 范围：目录、日程各页、活动详情、原文、状态、兑换码的 200 JSON 响应。错误响应、私人接口、能力型接口不加。
   - 校验器：响应 JSON 去掉 `cache` 字段（它每次都是"现在"）后的 SHA-256 前 128 位，写成 `W/"…"`。语义相同的两次响应得到同一个值；换代、来源状态或兑换码变化时随之变化。`cache.stale` 在源站恒为 false（主方案 §6.6、`publicCache`），去掉它不丢信息。
   - `If-None-Match` 按 RFC 9110 弱比较（含列表与 `*`），一致时回 304、不带正文，`Cache-Control` 仍为 `no-cache`。
2. **页面副本**（`apps/web/src/lib/public-api/store.ts`、`client.ts`）。
   - 公开响应原样存在本标签页 `sessionStorage`（键前缀 `hoyo:public:v1:`），记下 ETag 与核对时刻；读取时仍按 contracts schema 校验，不合就丢弃。配额满时从最久未用的开始删；存储不可用时照常请求、只是不复用。
   - 读取分两种：`cached` 在副本核对不满 `CLIENT_RECHECK_INTERVAL` 时直接用，否则带 `If-None-Match` 核对；`fresh` 立即核对（刷新按钮、重试、状态页）。304 时副本的 `cache` 改为这一刻的核对时间，新鲜期跨度沿用服务端给的。
   - 浏览器刷新（Navigation API `activation.navigationType`，不支持时看导航计时）进入的页面，只认本页加载之后的核对，等同于全部 `fresh`。
   - 请求一律 `cache: "no-store"`，新鲜与否只由这里决定，浏览器 HTTP 缓存不在中间悄悄复用。同一页面同时发出的同一读取只请求一次，共用原始正文、各自按自己的视图校验。
3. **首页按需、局部更新**（`features/schedule/load.ts`、`home.ts`）。
   - 目录、状态、兑换码只在本页第一次加载与用户刷新时读取，切换筛选不重读。
   - 本标签页读过的那一档日程（各页同代、同窗口、窗口仍从今天起）直接换上、不出骨架；副本过了核对间隔时只核对首页，304 就不再下载，变了再整档换上。
   - 没读过的筛选：旧列表淡化保留（`data-switching`），新的一档在后台读完后整体换上；读取失败时清空旧列表、照常显示失败（旧列表属于别的筛选，不能当成新筛选的结果）。刷新失败则旧列表照旧保留。
   - 标签页回到前台时，超过核对间隔的部分才用条件请求核对。
4. **详情页与原文弹窗**：读过的活动详情先显示副本，过了核对间隔在后台核对，只有 404 才改为"找不到这个活动"；原文在副本有可确认的版本且未过核对间隔时直接显示，上次没有可确认版本或用户点了重试时照旧向服务端读取。
5. **状态页**：刷新期间保留上次读到的内容（淡化），读完整体换上；读取失败照旧清空、写"状态未知"。状态页总是立即核对（`fresh`），不直接用副本。
6. **订阅页**：日历、浏览器通知、"选择接收方式"三处的公开能力改为经同一客户端读取 `/api/v2/status`（只取 `capabilities` 的宽松视图），与日程页、状态页共用副本。
7. **页头账号入口**（`components/header-auth.ts`）：服务端确认过（`/api/v2/me` 200 或页面发布 confirmed 身份事件）后，在本标签页记一个确认时刻（`hoyo:account-hint:v1`，只有时间，不含账号标识或任何凭证）。之后的页面先照提示显示「账号」，核对间隔内不再读 `/me`，过了在后台核对；浏览器刷新时照旧核对。Cookie 线索不在、核对得到非 200、或页面发布了非 confirmed 的身份事件时立即清掉。提示只决定页头文字，不授予权限；账号页、订阅页照旧自己向服务端确认身份。
8. **跨文档视图过渡**（`styles/base.css`）：同源导航启用 `@view-transition { navigation: auto }`，页头单独成组原地不动，正文 120 ms 交叉淡入；不支持的浏览器照常跳转，减少动效偏好下关闭。

## 价值

请求次数（本地 e2e，合成数据，`tests/e2e/soft-navigation.spec.ts` 逐项断言）：

| 操作 | 改动前 | 改动后 |
| --- | --- | --- |
| 首页 → 活动详情 → 回到首页（5 分钟内） | 4 + 1 + 4 | 4 + 1 + 0 |
| 再次打开同一活动详情（5 分钟内） | 1 | 0 |
| 切换游戏筛选（新组合） | 4（目录、状态、兑换码、日程） | 1（日程） |
| 切回读过的筛选（5 分钟内） | 4 | 0 |
| 副本超过 5 分钟后回到首页 | 4 次完整下载 | 4 次请求，带 ETag 的目录与日程首页回 304、无正文 |
| 已登录用户站内切换页面 | 每页 1 次 `/me` | 每 5 分钟 1 次 |
| 订阅页公开能力 | 3 次 `/api/v2/status` | 最多 1 次（5 分钟内从首页过来为 0） |

- 切换筛选、返回首页、再开详情都不再退回骨架；页头不再每页从「登录」跳成「账号」；状态页刷新不再整块消失。
- 刷新按钮与浏览器刷新的语义不变：总是向源站核对。

## 成本

- 同一标签页里，管理端刚发布的内容最多 `CLIENT_RECHECK_INTERVAL`（5 分钟）后才在站内切换时出现；刷新或新开标签页立即可见。这是对 ADR-0015"每次打开都取最新"的有意放宽，由所有者提出。
- 服务端每次公开读取多一次 SHA-256（公开响应上限 `PUBLIC_READ_LIMITS.responseBytes`），304 时省掉正文传输；D1 读取次数不变（仍要算出内容才能比较）。
- `sessionStorage` 容量由浏览器决定（常见为每源数 MB），满了按最久未用淘汰。
- 页头脚本在每一页都运行，不引入 contracts：`CLIENT_RECHECK_INTERVAL` 由 `_Layout.astro` 在构建时从 contracts 写进页头属性（`data-recheck-seconds`），读不到时按 0（每页都核对）。

## 安全影响

- 副本只含公开接口响应；私人接口仍 `no-store`、不经过页面副本（前端 §12.3）。账号提示只有一个时间戳，不含 user_id、邮箱、会话或 CSRF 值，不用来授权。
- `sessionStorage` 按标签页隔离、关闭即清空；退出、换账号时页面发布身份事件，提示随之清掉。账号页清除私人数据的行为不变。
- ETag 由响应内容派生，不含任何秘密；304 不改变 CSP、`no-referrer`、CORS 等安全头。

## 预算与容量影响

见"成本"。无新增供应商、计费项或迁移；D1 读取量不变，出口流量与客户端请求数下降。

## 回退

还原本 ADR 的提交即可：服务端不再给 ETag，页面回到每次完整读取；残留的 `sessionStorage` 键随标签页关闭消失。无数据变化。

## 备选方案

- **Service Worker 缓存公开读取**：能跨标签页复用，但需要处理更新、作用域与私人接口的排除，前端 §12.3 要求白名单与额外验收；本需求在同一标签页内已经够用。不采用。
- **`Cache-Control: max-age` 交给浏览器缓存**：ADR-0015 正是为避免"发布后最多 1 小时看不到"而改成 `no-cache`；浏览器缓存也不区分"用户刷新"与"站内切换"。不采用。
- **改成单页应用（客户端路由）**：改动面覆盖全部页面，与静态多页架构和现有 e2e 不符。视图过渡已能消除整页闪白。不采用。
- **页头直接按 Cookie 显示「账号」**：Cookie 只是线索，不能说明服务端仍认这个会话（前端 §12.3、`identity.ts` 不从 Cookie 推导身份）。不采用。

## 待确认

- 跨文档视图过渡只在 Chromium（e2e 桌面与手机项目）里验证过；不支持的浏览器仍是普通跳转，副本复用照常生效。
- 生产环境的 304 比例与节省的流量未测（需上线后看平台统计，不读生产日志）。
