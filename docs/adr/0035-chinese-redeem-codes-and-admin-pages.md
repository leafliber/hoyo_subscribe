# ADR-0035：支持中文兑换码，独立兑换码管理页并区分版本时间选择状态

- **状态**：已接受（所有者 2026-10-31 明确要求实施）
- **日期**：2026-10-31
- **提出者**：所有者：“帮我修复这个问题，并同时优化后台的显示，兑换码从设置开关页面分离出来，版本表明确区分已经选择完成的节点和没有选择时间的节点”。
- **需要所有者批准**：已由上述请求授权；无新增资源、权限、供应商或平台写入。部署另由所有者执行。

## 背景

2026-10-30 星穹铁道 4.7 前瞻的官方 `refreshCode` 返回三个中文兑换码。采集和正文读回各自的 ASCII 正则均拒绝它们，整批采集 incomplete，未入库或发布。管理页把空列表显示为“还没有发放”，混淆了读取失败与官方未发放。

ADR-0034 把直播管理嵌在运行开关页。ADR-0011 的版本表虽有确认徽标，已完成与待选节点仍混排，已选节点也持续展示全部候选和操作。

## 受影响的合同

| 文档 | 章节 | 现有规定 | 本 ADR |
| --- | --- | --- | --- |
| 主方案 / ADR-0030 | §3.1、§3.4 / 决策 1、6 | 原样采集官方兑换码、规则发布 | 修正实现的 ASCII 假设，支持汉字与原有字符；统一校验，不改变发布规则 |
| 前端 / ADR-0034 | §1.3 / 决策 6 | 直播及截止时间管理在运行开关页 | 移至独立 `/admin/redeem-codes/`，包含直播来源开关、维护解除、手动登记与截止时间登记 |
| 前端 / ADR-0011 | §1.3 / 管理端版本时间表 | 按游戏逐项采用或清除时间 | 明确“待选择时间 / 已选择时间”；未完成优先，完成版本收起，可展开更改 |

## 决策

1. contracts 定义唯一的兑换码校验，保留既有 1–64 字符格式上限，允许汉字及原有 ASCII 字母、数字、下划线、连字符。拒绝控制字符、空白、HTML 和正文分隔符；不翻译、不改大小写。采集、正文读回与公开响应共同消费。旧“待发放”正文仍按占位读回，不当兑换码。
2. 增加两个 2026-10-30 官方真实样本并离线回放，覆盖取码、正文读回、规则发布和公开读取；不调用真实发信或模型。
3. 独立“兑换码”页复用管理员会话及现有 API。运行开关页不再列直播兑换码来源。来源错误、最近成功读取、每场直播上次读取时间明确显示；空列表写“尚未读到兑换码”，不据此断言官方未发放。截止时间、理由、CAS 和页面内确认规则不变。
4. 版本表只根据已保存的确认值判断完成，不把候选值当成已选。未选择的节点展开；已选择节点展示时间与出处，修改操作收起。每个游戏先列未完成版本，再收起列出两项均已选的版本。采用、清除后重新读取服务端事实；引用锁、CAS、理由、推导和已发布事件语义均不变。

## 价值

中文兑换码能够进入首页和日历；后台能看出采集失败与真正已读到的数据，并优先处理尚未选择时间的节点。

## 成本

一张任务卡 F6-03，复用现有接口与样式，不新增数据库迁移、依赖或自动轮询。UID、SEQUENCE、订阅地址及既有用户配置不变。

## 安全影响

新页面仍为管理员独立权限域，noindex、不在公共导航。所有写入复用会话、CSRF、理由及版本校验。中文仍作为文本渲染；字符校验不放行 HTML、换行或结构分隔符。

## 预算与容量影响

不改变轮询频率、邮件日池、模型预算、Feed 容量或参数值，无新增 A.5 等式。恢复的兑换码照原有来源开关和发布规则处理。

## 回退

代码回退至 `d1d2c99` 会恢复旧页面与 ASCII 限制；已保存的中文兑换码仍是普通文本，无迁移需要回滚。已发布事件不删除或重新取号，已发通知无法撤回。

## 备选方案

- 只修采集正则：正文读回仍丢失中文，不能修好日历。
- 把空列表继续叫“未发放”：无法区分采集故障，保留误导。
- 自动选择版本候选：超出本次显示调整范围，改变人工确认语义，不采用。

## 待确认

无新增产品决策；正式部署及部署后的线上复核由所有者执行。
