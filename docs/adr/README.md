# 架构决策记录（ADR）

## 什么时候必须写 ADR

1. **要改动 `AGENTS.md` 第 3 节禁止清单中的任何一条**——这些是上一版被明确推翻的设计，恢复它们必须先说明价值、成本、安全和回退（主方案 §10.5）。
2. 要改动主方案 v2.1 或前端 v1.0 的任何**合同**（枚举、公式、权限边界、参数依赖等式）。
3. 要对已发布数据做破坏性迁移（DROP、改已发布 URL 语义、重写 UID）。
4. 实现中发现合同**自相矛盾或做不到**——停手，写 ADR 说明冲突，不自行改动业务含义让实现通过。
5. 要新增供应商、升级收费计划或扩大权限（另需所有者批准，ADR 不能代替批准）。

## 什么时候不需要

- 选择某个库、某种目录组织、某种测试写法——写进 PR 描述即可。
- 补充任务卡细节、修正导航层文档的错误。

## 编号与命名

`NNNN-简短标题.md`，四位顺序编号。已接受的 ADR 不删除；被推翻时新写一份并在旧的顶部标注 `被 ADR-NNNN 取代`。
