# ADR-0008：接受极大受阻私人预览可能无法在一次有效期内取全

- **状态**：已接受并登记；不改变 ADR-0006 的参数。
- **日期**：2026-10-02。
- **决定来源**：PR #68 最新 `486f272` 交付报告记载，执行者提出具体反例后，所有者答复“接受并记录此限制”。验收方本次独立复现反例；所有者另在验收会话明确授权 #68 通过后 squash，已合入 `cd232d5`。
- **证据边界**：所有者原答复由执行者在 PR 转述；本次独立核实的是行为与反例，没有把该转述称作验收方亲自收到的原答复。

## 背景与受影响要求

D2 §3.3 要求私人游标在 PUBLIC_CACHE_FRESH 内读取，并在过期后 409 preview_outdated；§3.5 和 ADR-0006 要求同一会话/同一 isolate 按时间窗口限制请求，续页也计数。此前 ADR-0006 要求测量合法最大分页并证明限流等待后仍能取全。

成功 Feed 的基础及更正上限能约束成功样本，不能约束已经 blocked 的全部候选数。后者仍应返回条目供缩小范围，不能静默截断后宣称完整。

## 事实与决定

生产路由、限流器、投影和字节分页下，11341 个合法基础条目、每项 8192 B，诊断为 blocked/base_node_limit，每页最多 63 项，需要 181 页。即使网络与处理零耗时，在 0/60/120/180/240/300 秒各取 30 页，也仅有 180 页/11340 项；360 秒请求第 181 页，实际返回 409 preview_outdated。

接受这种极大 blocked 预览可能始终无法在单次有效期内取全；相同范围重新取第一页仍可能重现。该限制补充 ADR-0006 的最大分页要求，不扩大成功或完整的定义。

- CALENDAR_PREVIEW_RATE_WINDOW、CALENDAR_PREVIEW_RATE_LIMIT、PUBLIC_CACHE_FRESH、PUBLIC_READ_LIMITS 均不改；运行值继续只取 contracts 注册表。
- 不新增总量截断、诊断枚举、平台资源、持久账本或收费项目；Feed 输出、投影与缩水守卫不变。
- 未取完保持未完成，blocked 保持受阻；不能显示完整、空日历或允许基于残缺预览完成启用确认。
- F3-04 遵守 retry_after_ms；409 后丢弃整轮、重新确认，重复过期时提示缩小已保存范围。不得自动无限刷新。
- P5-04 公开此限制并测目标环境成本；接受限制不等于平台 CPU、吞吐或账单已验收。

## 独立验证

验收方在 main `3ad7b05` 加 #68 的独立集成 `6efcd8e` 复现。大集合反例使用合成授权与内存 DB/cache，真实执行上述生产计算，Node wall 22.809 秒、CPU 25.118 秒；不是 Cloudflare 计费测量，也不声称联网耗时。

另以真实本地 workerd/D1 验证成功边界样本：1000 基础+1000 更正、解释项各 8192 B，32 页/2000 项，在实际 429 后按 retry_after_ms 推进注入时钟，含处理耗时 60.728 秒内取全；无 D1 写入。它证明该样本能完成，不证明任意候选集合都能完成。完整命令、变异与测量见 P3-15 卡末。

## 价值、成本与安全影响

保留已经批准的频率、新鲜期和响应保护，不为少见的巨大受阻集合增加资源或放宽开关。代价是该情况下用户需缩小范围才能取得完整权威预览；前端必须如实解释，不能靠无限重试掩盖。

权限、会话隔离、启用版本核对和 Feed 完整性要求不变；没有数据迁移或历史数据删除。

## 备选与回退

提高频率、延长有效期、截断集合均未获此决定批准，不实施。以后若要保证巨大 blocked 集合取全，先交测量和具体方案，再由所有者决定并另记 ADR；不能将本次接受推广为其他容量或费用豁免。
