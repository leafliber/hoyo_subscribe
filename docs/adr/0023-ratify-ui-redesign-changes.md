# ADR-0023：追认 #89 的三处界面调整：首页时间范围五档、不设全站故障横幅、日历订阅改称"链接"

- **状态**：已接受（所有者 2026-10-06 追认；#89 `c66242b` 已于 2026-10-04 合入并上线，本 ADR 无新代码改动）
- **日期**：2026-10-06
- **提出者**：验收方（2026-10-06 文档整理时发现 #89 有三处改动没有 ADR），所有者追认
- **需要所有者批准**：是，已批准。所有者 2026-10-06 原话："接受现状，补一份 ADR"。
- **与已有 ADR / 决定的关系**：修改 D1′（所有者 2026-09-22 定案，写在 F1-02 卡）的档位清单；修改 F1-04 的交付物"全站故障横幅"；修改前端 §9.1 的用词。ADR-0017 的"显示更多"档位序列（今天 → 近3天 → 近7天 → 近30天 → 全部）与本 ADR 一致。

## 背景

#89 是 web/UI 重设计（token 化设计系统、统一组件库与页面外壳），不是任务卡。合入时没有为下面三处写 ADR，2026-10-06 文档整理时发现。

1. **首页时间范围**：D1′ 为 今天 / 近3天（默认）/ 近7天 / 近30天 / 未来90天 / 全部。#89 起首页去掉"未来90天"：`apps/web/src/features/schedule/ranges.ts` 从 contracts `BROWSE_RANGES` 过滤掉 `90d`，旧链接 `range=90d` 按"全部"读。#89 提交说明给的理由是它与"全部"重叠、命名也与其余档位不一致。"全部"取服务端窗口（`FEED_FUTURE_DAYS` = 180 天），覆盖 90 天，去掉这一档不会让任何条目看不到。contracts 与公开接口仍接受 `90d`。
2. **全站故障横幅**：F1-04 交付了 `ServiceFaultBanner`，挂在 `_Layout.astro`，监听 `hoyo:service-fault` 事件。但应用代码里没有任何地方发出这个事件（只有 E2E 手动派发），横幅从未在真实故障时出现。#89 删除了该组件、`components/feedback/` 目录与对应的 DOM 用例。现在故障说明由各功能区自己的状态区按 `lib/errors/feedback.ts` 的映射显示（日程、订阅保存、日历、邮件、账号、恢复）；服务状态页 `/status/` 公开各能力与来源的状态。
3. **日历订阅区域的用词**：前端 §9.1 用"地址"（地址状态、复制地址、管理日历地址、停用/重置日历地址）。#89 统一改称"链接"（复制订阅链接、管理订阅链接、重置链接）；四项事实改为 链接状态 / 使用的设置 / 内容输出 / 日历应用拉取；客户端说明并入"查看订阅步骤"折叠。指的仍是同一个私人 Feed URL，页面照样提示它是私人凭证。

## 受影响的合同

| 文档 | 章节 | 现有规定 | 本 ADR |
| --- | --- | --- | --- |
| 前端 / F1-02 卡 | §13 D1′ 档位 | 六档，含"未来90天" | 首页五档：今天 / 近3天（默认）/ 近7天 / 近30天 / 全部。旧链接 `range=90d` 按"全部"读；contracts `BROWSE_RANGES` 与公开接口保留 `90d` 以兼容 |
| F1-04 卡 | 交付物"全站故障横幅" | 挂在全站外壳 | 不设全站故障横幅；故障由各功能区状态区与服务状态页说明。前端 §11.3 的反馈要求对这些状态区照样适用 |
| 前端 | §9.1 日历订阅 | "地址"系列用词；四项事实为 地址状态 / 配置状态 / 输出状态 / 客户端情况 | 界面统一称"订阅链接 / 链接"；四项事实为 链接状态 / 使用的设置 / 内容输出 / 日历应用拉取，客户端情况在"查看订阅步骤"里说明。各项含义不变 |

## 决策

接受上述三处现状为合同。

附带说明：首页档位清单现在写在 `apps/web/src/features/schedule/ranges.ts`。按 D1′"档位定义放 contracts，前端不得另写一套"的原则，下次改动这一块时应把首页档位清单移进 contracts（纯重构，不改行为）。不另立卡。

## 价值

- 首页筛选少一个与"全部"重叠的档位，"显示更多"逐档续读的序列更短。
- 删去一个从未被触发、却让人以为有全站兜底的组件。
- "订阅链接"更贴近用户在日历应用里实际粘贴的东西。

## 成本

无新改动。对已上线用户：带 `range=90d` 的旧链接显示为"全部"，内容只多不少；公开接口不变。

## 安全影响

- 档位与用词只改呈现，不改公开接口与权限。
- 没有全站横幅后，故障只在发生的功能区显示。§11.3 要求的"保留可用内容和草稿、标明未完成操作、提供受控重试"由各功能区承担，不再依赖全站兜底。
- "链接"的说明保留了私人凭证的警示；完整链接仍不写入分析日志、错误追踪与截图（§9.1、硬规则 7）。

## 预算与容量影响

无。

## 回退

- 首页档位：在 `ranges.ts` 去掉过滤即可恢复第六档，contracts 与接口不用改。
- 故障横幅：需要时另立卡，从 F1-04 的实现（`bd8fb79`）恢复组件，并把各功能区的故障接到同一事件上。
- 用词：改回"地址"只是文案改动。

## 备选方案

恢复 D1′ 原样、重新挂横幅、改回"地址"。所有者选择接受现状。

## 待确认

无。
