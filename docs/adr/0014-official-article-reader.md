# ADR-0014：「查看官方公告」改为打开原文弹窗，正文取自本站保存的版本，在浏览器里整理成可读文字

- **状态**：已接受（P3-22 实施）
- **日期**：2026-10-05
- **提出者**：所有者提出需求；实施方核实官方接口的跨域限制后给出方案
- **需要所有者批准**：是，已批准。所有者 2026-10-05 先要求"在用户浏览器请求官方页面，在浏览器中解析，用模态框展示原文"。实施方实测发现浏览器读不到官方接口（见背景），给出替代方案。所有者选了"本站存档原文"，并要求"注意保持人类可读性"。
- **与已有 ADR 的关系**：ADR-0001 的采集参数不变；ADR-0009 的"草稿与候选分离、人工批准才发布"不变。

## 背景

事件详情的「查看官方公告」和侧栏「公告链接」直接跳到 `official_url`。这个地址不是可读的网页：

- 三个游戏公告来源存的是正文接口 `getAnnContent`，一次返回全部公告的 JSON。单篇官方页的地址格式从未核验过，`sources/articles/ingest.ts` 刻意没有虚构；
- 米游社来源存的是资讯列表接口。

所以用户点开看到的是一大段 JSON，读不了。

所有者希望由浏览器直接请求官方、在本地解析。实施方 2026-10-05 在本机做了核验，每个来源只发 GET，不带凭据：

| 请求带的 Origin | 官方公告接口返回的 `Access-Control-Allow-Origin` |
| --- | --- |
| `https://hoyo.airo.cc`（本站） | 没有 |
| `null`、`http://localhost:4321` | 没有 |
| `https://sdk.mihoyo.com`、`https://webstatic.mihoyo.com`、`https://ys.mihoyo.com`、`https://www.miyoushe.com` | 原样返回该 Origin，且 `allow-credentials: true` |

从本站发出的预检 `OPTIONS` 返回 204，同样没有放行头。官方接口按白名单只允许米哈游自家域名跨域读取，本站页面里的脚本读不到响应。

另外两条路也不通：

- **代理转发**：由 Worker 代为请求官方再转给浏览器。这等于绕开官方的白名单，违反 AGENTS.md 规则 6。每个用户点一次就请求官方一次，也违反主方案 §3.1"全部用户共用采集结果"。
- **嵌入官方页面**：游戏内公告页 `sdk.mihoyo.com/hk4e/announcement/index.html` 在普通浏览器里是空白。实测 `#root` 没有内容，也没有发出接口请求，它依赖游戏客户端。这个页面还会加载米哈游的统计脚本。

现有能力：Worker 采集时已经从官方取得每篇公告的正文，存成不可变的文章版本（主方案 §3.2）。正文块保留官方原始 HTML 片段。

## 受影响的合同

| 文档 | 章节 | 现有规定 | 本 ADR |
| --- | --- | --- | --- |
| 主方案 | §8.2 接口表 | `/api/v2/catalog、events、status`：GET；公开有限窗口/同代分片与状态；不创建身份 | 在 `events` 下新增子资源 `GET /api/v2/events/{eventId}/articles`。同样公开、按代次、有界，不创建身份 |
| 前端 | §5 事件详情 | 官方链接易于找到；正文先使用受控文本结构，需要展示公告内容时按数据转义，不直接执行公告 HTML；主要操作含"查看官方公告" | 不变，本 ADR 按此实现。「查看官方公告」打开原文弹窗；官方接口地址留在"官方来源"里，标为"官方数据源" |
| P3-14 交接 | `apps/worker/src/public/README.md` | 公共读"不返回文章正文块" | 详情和列表仍不返回。原文只由新子资源返回，绑定条件与公告发布时间相同 |

业务枚举、发布语义、提醒规则、日历与邮件都不变。

## 决策

1. **原文接口** `GET /api/v2/events/{eventId}/articles`：
   - 绑定条件与详情里的公告发布时间完全相同：证据已发布且不晚于本代发布，本代投影与日历投影一致，候选已批准且逐字段匹配。条件不成立的节点不给原文；
   - 每个节点绑定出的文章版本去重，按本站抓取时间新到旧排列。正文块按原样返回，并附本站抓取时间、版本号、官方发布时间（未知为 null）、完整性和官方数据源地址；
   - 不返回版本 ID、候选、证据或任何内部字段。查询走 `PUBLIC_NOTICE_SQL` 同一条绑定，只多给出版本 ID 供内部读取正文；
   - 正文按抓取时间新到旧累计字节，超过 `PUBLIC_READ_LIMITS.responseBytes` 时明确返回不可用（503），不返回截断的原文。不新增参数；
   - 缓存与其他公共读取相同（ADR-0015 起为 `no-cache`）。没有发布代次时 503，没有此事件时 404。
2. **网页**：
   - 页首「查看官方公告」改为按钮，打开原文弹窗。侧栏改为「阅读公告原文」按钮加「官方数据源」链接，链接悬停提示"官方接口返回的原始数据，适合核对"（原为一行说明文字，ADR-0015 删去）；
   - html 块只交给 `DOMParser` 惰性解析，解析出的文档不执行脚本、不加载资源。节点从不放进页面，只读文字和少数校验过的属性，按白名单重建：
     - 保留段落、标题（降两级）、列表、表格（含合并单元格）、官方折叠段（展开状态照原文）、加粗、链接；
     - 丢弃颜色、字号等样式，以及官方用作间距的空段落；
     - 官方转义的 `<t>` 时间标签只留时间。这条规则与审核页可读文本共用 contracts 的 `unwrapOfficialTimeTags`；
     - 游戏内链接 `javascript:miHoYoGameJSSDK.openInBrowser('…')` 取出其中的网址，只接受 http/https，其他 `javascript:` 链接只留文字；
     - 图片只给"查看图片"链接，不自动加载；脚本、框架、样式、表单整段跳过；
   - 每篇原文写明"本站抓取于 …"、第几版和官方数据源链接（弹窗开头原有一段说明，ADR-0015 删去）。版本不完整时显示 contracts 的 `ARTICLE_COMPLETENESS_NOTES`，只说缺了什么，不暗示"没有活动"；
   - 没有可确认的原文版本、读取失败都如实说明，读取失败可以重试；
   - 只有正文区域滚动，标题栏和关闭按钮始终可见。沿用站内弹窗的焦点约定：背景设为不可操作，Esc 关闭，关闭后焦点回到入口。
3. **contracts**：
   - 完整性状态全集 `ARTICLE_COMPLETENESS_STATES` 从 Worker 移入 contracts，公开响应按同一枚举校验；
   - 新增 `PublicEventArticlesResponseSchema`。

## 价值

- 用户点「查看官方公告」看到的是排好版的公告正文，不再是 JSON。
- 用户能对照原文核对推算出的时间（ADR-0011、ADR-0013）和"预计"类时间。看到的就是本站发布这条事实时依据的那一版。
- 官方接口地址仍然容易找到，用途写清楚了。

## 成本

- 不需要迁移，不新增参数，不新增供应商或计费项。
- 已部署的页面需要和 Worker 一起更新，否则旧页面仍然只是跳转链接。

## 安全影响

- **新增公开读取面**：过去公共接口只给证据片段，现在可以读到本站保存的公告全文。这些内容本来就是官方公开发布的公告。边界如下：
  - 只读本代已发布事实按上述条件绑定出的版本，不读没有绑定到已发布事实的版本；
  - 正文里提到、但尚未审核的活动，不会因此进入日程、日历或通知；
  - 弹窗明确标为"官方公告原文"，不当作本站事实展示。
- **注入**：公告 HTML 从不插进页面。`DOMParser` 生成的文档没有浏览上下文，不执行脚本、不触发事件属性、不加载图片。e2e 覆盖了 `<script>`、`onerror`、`javascript:` 链接、`<iframe>`、`<style>`，断言这些都没有生效，页面也没有向第三方发请求。
- **外链**：一律 `noopener noreferrer`，并设 `referrerpolicy="no-referrer"`。打开弹窗不会向官方或任何第三方发请求。
- **身份与存在性**：不读 Cookie、不鉴权、不建身份。没有此事件时的 404 与详情相同。原文是否存在本身就是公开信息，不构成新的存在性差异。

## 预算与容量影响

- 每次打开弹窗的查询：代次 1 次、事件节点 1 次、证据绑定（每 100 个节点 1 次）、正文 1 次、代次复核 1 次，与详情同一量级。
- `PUBLIC_ARTICLES_SQL` 按版本 ID 点查。A-P3-PUBLIC 基准实测 rows_read 为 7，加 2000 条无关历史后仍是 7。
- 单次响应不超过 `PUBLIC_READ_LIMITS.responseBytes`（512 KiB）。浏览器按 `max-age` 缓存，重复打开不会重复请求。
- 不调用 Workers AI，不发邮件。A.5 等式不受影响。

## 回退

- 把页首和侧栏按钮改回原来的链接、去掉路由即可，没有不可逆的数据。
- contracts 的枚举搬迁不改取值。Worker 侧原导出路径仍然可用。

## 备选方案

1. **浏览器直接请求官方接口**（所有者最初的要求）：官方按 Origin 白名单放行，本站读不到，见背景的实测。
2. **Worker 代理转发**：绕开官方白名单，违反 AGENTS.md 规则 6；按用户点击次数请求官方，违反 §3.1 共用采集。不采用。
3. **弹窗里嵌入官方游戏内公告页**：在普通浏览器里是空白，还会加载统计脚本。不采用。
4. **只把链接文案改成"官方数据源（JSON）"**：成本最低，但用户仍然读不到原文。所有者选了弹窗。
5. **服务端转成纯文本**（复用审核页的 `readableBlockText`）：表格会被压成"甲 | 乙"一行行的文字，不如浏览器里重建表格好读。所有者要求在浏览器里解析、保持可读，故不采用。
6. **弹窗里直接显示图片**：会让本站页面向官方图床发请求，也偏离"受控文本结构"。先只给链接，需要时另议。

## 待确认

- 米游社来源的正文通道已停用（403，P0-02），弹窗只能说明"只有标题"。单篇官方页的地址格式仍未核验，不在本 ADR 范围。
- 官方在本站审核之后又改过的公告，弹窗显示的是审核所依据的那一版，并写明本站抓取时间。不提示"还有更新的未审核版本"。
