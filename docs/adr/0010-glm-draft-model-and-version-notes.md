# ADR-0010：AI 草稿改用 glm-5.3-flash，版本公告纳入起草，旧草稿按新组合重起草

- **状态**：已接受（P3-18 实施）
- **日期**：2026-10-04
- **提出者**：验收方根据线上后台情况提出，所有者决定换模型
- **需要所有者批准**：是，已批准。所有者 2026-10-04 在对话中决定"换 glm-5.3-flash"，并要求据后台情况处理与版本相关的问题。
- **与 ADR-0009 的关系**：取代 ADR-0009 中"模型 profile"与"单次预占"两项；草稿与候选分离、人工批准才发布、日上限取 `AI_SOFT_DAY` 等其余决定不变。

## 背景

ADR-0009 上线当天（2026-10-04），管理端在所有者登录的会话里只读盘点了 64 条待审候选：

| 草稿状态 | 条数 | 说明 |
| --- | --- | --- |
| 就绪，有日程 | 24 | 其中 17 条的开始是"X.Y版本更新后"，5 条的结束是"X.Y版本结束/期间"，都只能存成"未定时刻" |
| 就绪，无日程 | 35 | 抽查多为说明、声明、FAQ、永久开放内容、商店；判断基本正确 |
| 跳过：正文超长 | 3 | 恰是三款游戏的版本更新说明（7–9 千字），超过 24,000 字节输入上限 |
| 跳过：正文不完整 | 2 | 内容在图片里（`review-image-borne`），按合同不能批准 |

所有者反馈模型"太差，和版本相关的无法正常识别"。草稿里看到的具体问题有三类：
- 分阶段赛季被拆成三组开始/结束；
- 把"关闭购买"的时刻当成第二个结束；
- 版本更新说明完全没有草稿。

这些说明里正写着版本时间：更新开始时刻、"预计5个小时完成"；星铁和绝区零还明确写了版本结束时刻。

## 决策

1. **模型**：`@cf/zai-org/glm-5.3-flash`（2026-08 上线，320B 总参数、18B 激活，原生多模态，100 万上下文）。
   - 单价：13,636 / 45,455 Neurons 每百万输入/输出 token（官方价目页 2026-10-01）。该模型需要 Workers Paid 账户，用量仍计入每日 10,000 Neurons 免费额度。
   - 思考不能关闭，`reasoning_effort` 取 `low`；temperature 0.3。
   - 输出上限用 `max_completion_tokens` = 8,000，这个上限含思考在内。
2. **提示词 v2**（`draft-prompt-v2`）：
   - 分阶段活动作为一个事件：最早开始记 start，最晚结束记 end，中间各阶段记 phase_unlock 并写阶段名；
   - 每个事件最多一个 start、一个 end；"关闭购买/停止兑换"不是节点；永久开放、商店、礼包、折扣不算日程；
   - 长公告逐个列出限时活动与卡池；
   - 版本公告另输出 `version_window`：版本号、更新开始、更新时长原文、版本结束，必须逐字引用原文。
3. **版本时间只进说明，不进候选**：服务端逐字核对 `version_window` 的每一项，完整时刻用官方 UTC+8 解析，核对不到的丢弃并提示。核对通过的部分作为第一条说明展示给审核员，例如"版本时间（逐字核对）：4.6 版本更新开始 2026-09-28 06:00（北京时间），预计5个小时完成；版本结束 2026-11-11 06:00"。它不改变候选内容，也不参与发布。
4. **输入上限与预占**：
   - 输入上限从 24,000 字节提高到 64,000 字节，三份版本更新说明都能放下。
   - 每次调用按本篇提示词的实际字节数预占：输入 token ≤ 字节数，输出按 8,000 计。典型公告约 426 Neurons，单次最大 1,238，不超过 `AI_SOFT_DAY`。之后按平台回报的 neurons 结算。
5. **旧草稿重起草**：`profile_ref` 由模型、提示词版本和 Schema 组成。它变化后，待审候选的旧草稿视为过期，watchdog 照常每轮最多补排 20 条按新组合重新起草，调用次数从头计。
6. **采用绑定草稿版本**：采用接口新增必填的 `expected_draft_updated_at`。草稿在审核员打开后被重新起草过时返回 409，页面重新读取。这样不会采用审核员没看过的内容。

## 价值

- 用后台里的同一批真实公告实测（2026-10-04，共 3 次调用）：
  - 「霄练赛季」正确识别为开始、两个阶段开启、结束；
  - 纪行公告忽略了"02:59 关闭购买"；
  - 星铁 4.6 版本更新说明逐个列出各项活动，并正确摘出版本 4.6、更新开始 2026/09/28 06:00:00、"预计5个小时完成"、版本结束 2026/11/11 06:00:00。
- 三份版本更新说明不再被跳过；审核员能直接看到版本时间，为下一步的版本时间表打基础。

## 成本

- 实测典型公告 22–25 Neurons/篇，约为原模型的 2 倍；版本更新说明约 100–200 Neurons/篇。
- 部署后约 64 条待审候选重起草，预计约 2,000 Neurons，日上限内分几轮 watchdog 完成。
- 不新增迁移、绑定或秘密。

## 安全影响

- 采用接口增加草稿版本 CAS，消除"后台重起草与审核员点击"之间的竞态。
- 模型仍然只拿到官方正文，没有工具或写权限；版本时间摘录只进说明，不进入候选和发布。
- 新模型属于同一 Workers AI 产品，不新增供应商或权限。

## 预算与容量影响

`AI_DRAFT_RESERVATION`（单次最大预占）由 203 变为 1,238，仍满足 `ai-draft-reservation-within-soft`；等式新增推理档位合法性检查。日上限仍为 `AI_SOFT_DAY` = 6,000。同账户其他应用每日 Workers AI 用量仍需少于 4,000 Neurons。

## 回退

- 改回 ADR-0009 的 profile 需要发布一次代码。草稿会按回退后的组合重新起草，已采用、已发布的候选不受影响。
- 立即停止新的调用：关闭 `model_enabled`。

## 待确认（下一步，需所有者批准后另立卡）

**版本时间表**：
- 由版本公告里核对通过的 `version_window` 建立"游戏 × 版本"的时间表，审核员每个版本确认一次。
- 确定性推导：
  - "X.Y版本更新后" 推导为更新**日期**（仅日期，`deterministic_derived`）；不推出时刻，因为合同 §3.3 规定"预计维护五小时"不是实际开服。
  - "X.Y版本结束" 在官方写明版本结束时刻时推导为该**时刻**（`deterministic_derived`，可用于提醒）。
  - 推导依据在详情页展示。
- 这一步涉及新表、推导规则，以及已发布事件的更正流程，须另立 ADR。
