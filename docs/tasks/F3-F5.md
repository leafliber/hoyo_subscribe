## F3 · 账号与日历闭环

前置门禁：**G-P2**（账号纵向闭环）、**G-D3**（前端状态视图合同）；F3-04 另需 **P3-07** 与 **G-D2**。

### F3-01 · 登录与验证码页

| 项 | 内容 |
| --- | --- |
| 允许改动范围 | `apps/web/src/features/auth/**`、`apps/web/src/pages/login.astro` |
| 继承合同 | 前端 §7.1、§7.2、§13.3；主方案 §4.1—§4.5 |
| 验收 ID | U13、U14 |

**交付物**

- 表单：邮箱、申请验证码、**可整段粘贴的验证码输入框**、确认按钮。
- 验证码位数、重发间隔、有效期**来自服务端真实挑战状态与参数注册表**，页面不另写常量。
- 等待状态分别说明"正在申请""正在验证""正在完成登录"，提交期间避免重复点击。
- 会话名额已满：展示**脱敏设备列表**（标签、`created_at`、`renewed_at` + 滞后说明），由用户选择撤销后激活。
- 前端 §7.2 的八种挑战情况全部有对应交互。

**关键约束（红线）**

- **申请验证码使用不泄露账号存在性的统一响应**；不无条件写"邮件已送达"；暂停注册时展示**全局**注册状态，**不按邮箱显示"账号不存在"**。
- 邮件平台/全局额度故障时显示真实全局不可用状态，**不模拟发码成功**。
- 明确重发不重置最初有效期限或累计错误次数；请求超时重试复用同一幂等上下文，**不自动变成一次新的发信意图**。
- preauth 丢失或过期时提示重新建立认证流程，**不统一归咎于验证码错误**。
- 邮箱输入说明遵守身份规范：**不删除点号、加号或标签**，不猜测用户想登录另一个地址，不把登录输入当换邮箱。内部 HMAC 等实现细节不放入主流程。
- **进入 pending 不等于普通账号权限已经可用**；登录成功仅恢复身份，不代表保存、Feed 开通或外部客户端设置成功。
- **不自动踢出旧设备。**

### F3-02 · 恢复码交付与恢复入口

| 项 | 内容 |
| --- | --- |
| 前置 | F3-01 |
| 允许改动范围 | `apps/web/src/features/auth/recovery/**`、`apps/web/src/pages/recover.astro` |
| 继承合同 | 前端 §7.3、§7.4；主方案 §4.6 |
| 验收 ID | U15、U25 |

**交付物**

- 首次启用 Feed / 邮件 / Push **之前**要求保存当前恢复码并明确确认；提供单独复制或下载。
- 恢复入口：**先让用户选择目的，再输入恢复码**，两个流程各自说明后果。
- 紧急停用：只显示停用结果，**不展示私人数据**，并**明确告知恢复码仍然有效**。
- 恢复登录：激活后**立即显示新恢复码并要求保存确认**；确认前只提供查看、导出、保存新码、删除账号，**启用通道与换邮箱一律置灰并说明原因**。

**关键约束（红线）**

- **"紧急停用不消耗恢复码"必须写在按钮旁边，不得藏进帮助页。**
- **"保存新码"不是可跳过的提示步骤，而是恢复会话的准入条件**——刷新、断网或关标签页都不能让用户落到既无旧码也无新码的状态。
- 恢复码**不进入普通偏好导出、URL、本机长期缓存或遥测**。
- 说明"旧码不能再次取回"；无法再显示旧码时按最近认证和轮换合同恢复操作，**不假装服务器仍能展示旧码**。
- 恢复后说明原日历地址已失效、邮件与 Push 已暂停，**不能把暂停显示为订阅内容丢失**。
- 新邮箱仍须验证；发送整体故障时**不伪造新邮箱验证**。
- 所有账号证明均丢失时**不提供"仅凭说明邮件接管"的界面承诺**。

### F3-03 · 账号与设备页、两种退出

| 项 | 内容 |

| 验收 ID | U14a、U24、U29 |

**交付物**

- 分区：账号信息 / 登录设备 / Push 绑定 / 恢复与数据 / 危险操作。
- 会话列表字段：标签、`created_at`、`renewed_at` 及**滞后不超过一个 `SESSION_RENEW_INTERVAL`** 的说明。
- 退出对话框**两个独立按钮**：「仅退出账号」与「退出并暂停本浏览器通知」。
- 删除账号进行中的状态展示：权限与发送已停止 / 数据仍在清理 / 清理完成（**只有有证据时才显示完成**）。

**关键约束（红线）**

- **登录会话与 Push 绑定分组展示**，不把"设备"当万能对象；**不承诺撤销会话会自动撤销其 Push**。

- **不能因为长期不访问网页就断言账号不活跃**（U14a）；Feed 使用等信号按主方案处理。
- 删除确认说明将停用本站权限和通道，但**不能即时擦除已送达邮件、外部日历副本或尚未到期的备份**。
- 删除账号、轮换恢复码使用用途限定的最近认证；**Feed 管理不混入这套额外 OTP 要求**。

### F3-04 · 日历订阅区域

| 项 | 内容 |
| --- | --- |
| 前置 | F3-01、P3-07、G-D2 |
| 允许改动范围 | `apps/web/src/features/channels/calendar/**` |
| 继承合同 | 前端 §9.1；主方案 §6.1、§6.5、§6.6、§4.7 |
| 验收 ID | U20、U21a |

**交付物**

- **四种信息分开显示，不合并成一个绿色开关**：地址状态 / 配置状态 / 输出状态 / 客户端情况。
- 首次启用展示实际预览、提醒关联节点、客户端限制及只读地址用途，由用户确认。
- 取得地址后显示"日历订阅地址已创建"+「复制地址」+「查看订阅步骤」。
- "管理日历地址"分组：关闭日历提醒 / 停用地址 / 重置地址 / 再次启用，四种后果各自说清。
- **缩水守卫的前端表现**：显示「本次输出未通过完整性检查，已暂停更新以保护你现有的日历内容」，给出上次成功输出的时间与条目数，并提供重试与联系入口。

**关键约束（红线）**

- **守卫拦截不得显示成普通网络错误，更不得建议用户重置地址或重新订阅**——那恰好会把守卫保住的旧内容丢掉。
- 客户端情况**依据实测资料**展示；**未知保持未知**，不得映射为支持。G-P0-CAL 未通过时，**不开放声称"日历提醒可用"的正式版本**。
- 完整地址是只读凭证：**不写入分析日志、错误追踪、公开截图或配置分享**；**复制成功不等于外部客户端已添加**。
- 地址通过**专用所有者接口按需读取**，不混入普通账号摘要或本地偏好。
- 最近拉取时间必须标为"客户端曾请求地址"，并说明**按天合并记录、最多滞后一个记录间隔**；**不得据此显示"所有设备已同步"或"提醒已送达"**。
- 启用/停用/重置**不额外要求 OTP**；重置结果不确定时核对现有状态，**不反复发起新的重置**。
- **不要把单次下载导入宣传为持续订阅**；客户端快捷接入按钮仅在对应方式实测后提供。
- 停用**不能擦除已经下载的副本**。

### F3-05 · 真实云配置联调与首次保存引导

| 项 | 内容 |
| --- | --- |
| 前置 | F3-01、F2-03、P2-06 |
| 允许改动范围 | `apps/web/src/features/subscription/**`、`apps/web/src/features/auth/**` |
| 继承合同 | 前端 §7.1、§13.1；主方案 §4.4、§5.1 |
| 验收 ID | U12、U15a |

**交付物**

- 主流程按前端 §7.1 打通：公开浏览 → 编辑草稿 → 申请验证码 → 激活会话 → 读取云配置并确认草稿处理方式 → 保存订阅 → 保存恢复码 → 确认日历预览 → 启用日历 → 复制地址。

**关键约束（红线）**

- **预选不是已保存**，视觉区分沿用保存状态机。
- **不出现可点却必然失败的按钮**（U15a）。
- 登录后回到发起操作的页面；**返回地址仅允许站内白名单路径**。
- 邮件与 Push **不附带开启**；用户中途退出时已保存云配置不回滚。
- 新游戏**不自动加入已有用户的 `scope`**。

## F4 · 邮件与账号维护

前置门禁：**P4-05**（两层同意 API）、**P4-06**（退订）、**G-D3**。

### F4-01 · 邮件提醒两层呈现与同意流程

| 项 | 内容 |
| --- | --- |
| 允许改动范围 | `apps/web/src/features/channels/email/**` |
| 继承合同 | 前端 §9.2、§9.4；主方案 §7.5、§9.1 |
| 验收 ID | U22、U22b |

**交付物**

- **必须按两层呈现，不能并成一个开关**：
  - 邮件提醒（席位）——「活动取消或时间变了，用邮件通知我」，默认关闭。
  - 常规提醒邮件（子名额）——「常规提醒和新活动也发一份邮件」，**默认关闭**，附说明"已启用日历提醒的话，日历本身会提醒、新活动也会直接出现，这一项通常不需要"。
- 启用前展示：当前已验证邮箱、已保存内容范围、日限频、租期、预算降级说明；**分别记录两层同意**。
- 状态四维分别呈现且可并存：同意/主动关闭、租期/名额、可投递性、全站预算/发送故障。
- 跨通道说明：各通道独立，**没有自动故障转移**，**无法控制外部日历去重**。

**关键约束（红线）**

- **数值读取实际服务参数**，前端不复制 `MAIL_SEAT_LEASE`、`MAIL_USER_BASE_DAY`、`MAIL_USER_URGENT_DAY` 的第二套值。
- 额度说明用"最多发送机会，**非保证每条必达**"，并说明**同一时段的多条提醒会合并成一封**（避免用户把"每天一封"理解成"每天只告诉我一件事"）。
- 日口径按 **UTC** 解释，**不按浏览器本地午夜自行重置**。
- 租期说明"**只要你还在用（包括外部日历在拉取），名额不会因为没回网页而被收走**"；**不把"仍能登录"当作邮件服务仍有效**。
- 第二层默认关闭**必须讲清原因**，否则用户会以为功能缺失。
- 拒绝、抑制或投诉**不能由前端重新勾选直接解除**；换邮箱后业务邮件重新同意。
- 关闭邮件**不影响日历、账号登录或浏览器通知**。
- 若展示投递记录，只按实际证据标注"已提交平台""收件服务器已接受""延期""退信""未知"；**不显示"用户已读"**。首版不新增逐封用户收件箱。

### F4-02 · 名额不足体验

| 项 | 内容 |
| --- | --- |
| 前置 | F4-01 |
| 允许改动范围 | `apps/web/src/features/channels/email/**` |
| 继承合同 | 前端 §9.2 名额段落 |
| 验收 ID | U22a |

**这是本产品出现频率最高的一次拒绝**：`MAIL_SEATS_MAX = 50` 远小于 `ACCOUNT_MAX_STORED = 500`，多数用户第一次点"开启邮件提醒"都会撞上它。**不能只丢一行"名额已满"。**

**交付物（四项缺一不可）**

1. **当前状态**：邮件名额已满，且这是**内测期的预算限制，不是账号有问题**。
2. **替代方案放在最显眼位置**：个人日历 + 日历提醒**默认可用、不占名额**，大多数提醒需求它都能满足；直接给出「去启用日历提醒」按钮。
3. **差别说明**：没有邮件名额时，仍会失去的是「取消/改期的主动通知」——**如实写，不粉饰**。
4. **是否可候补**：有候补就说明规则，没有就直说暂不提供；**不承诺具体开放时间**。

## F5 · 可选 Push

前置门禁：**P6-03**（目标浏览器与网络验收通过）。

### F5-01 · 本浏览器通知

| 项 | 内容 |
| --- | --- |
| 允许改动范围 | `apps/web/src/features/channels/push/**`、Service Worker |
| 继承合同 | 前端 §9.3；主方案 §7.8 |
| 验收 ID | U23 |

**交付物**

- 按钮统一为 **「在当前浏览器开启通知」**，仅在 Push 能力开放后出现。
- 浏览器权限与服务端绑定**分别展示**：不支持 / 未授权 / 已拒绝 / 允许；等待激活 / 已激活 / 已暂停或失效。
- 权限允许后创建 pending 绑定，显示"正在验证本浏览器接收能力"；完成可见激活与 receipt 合同后才显示"**本浏览器接收验证通过**"。

**关键约束（红线）**

- 用户主动点击前，**不申请系统权限、不创建 Push 绑定、不发送测试**。
- **平台已接受请求不等于客户端激活成功。**
- 权限拒绝时说明需在浏览器设置中调整，**不循环弹窗**。
- 绑定属于其他账号时解释冲突并保留当前账号边界，**不通过 endpoint 自动认领或删除他人绑定**。
- 测试、重试、续期受真实额度与状态约束；显示可重试时间，**不靠无限测试或静默心跳维持"在线"**。
- **激活通过也不承诺未来每条必达。**
