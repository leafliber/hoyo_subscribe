# P1 · 契约、数据库与安全原语

> 唯一主要目标：**把两份合同里不变的部分固化成代码里唯一的定义源。**此后任何阶段都不再重新定义枚举、参数或条件提交方式。
> 依据：主方案 §3.3、§5.1、§8.1、§8.3、§9.1—§9.2、§10.5、附录 A。
> 本阶段**不依赖 P0 结论**，可立即开始。

### P1-02 · contracts：枚举、时间语义与邮箱身份规范化

| 项 | 内容 |
| --- | --- |
| 前置 | P1-01 |
| 允许改动范围 | `packages/contracts/**` |
| 继承合同 | §3.3、§4.1、§5.1；`CONTRACTS_BASELINE.md` §1、§3、§4 |
| 验收 ID | A-P1-CONTRACT |

**交付物**

- 全部枚举（`CONTRACTS_BASELINE.md` §1）作为 TS 联合类型 + Zod schema，单一导出。
- 时间类型：`ExactTime`（UTC 毫秒整数）与 `DateOnly`（`YYYY-MM-DD`），**类型层面不可互转**；每个时间值携带 `source_timezone`、`raw_expression`、`time_basis`、`precision`。
- 订阅配置 `schema_version: 3` 的 Zod schema：有限枚举、去重排序、**拒绝未知键与额外层级**；非空约束以 `state` 为条件（`uninitialized` 时放行空 `scope`/`calendar.event_types`）；`rule_ids` 允许为空数组。
- 邮箱身份规范化纯函数：去两端空白、规范域名并小写、本地部分折叠小写用于**身份键**；**不删除点号、加号或标签**；**不做供应商特例合并**；首版支持 ASCII 本地部分。
- 提醒规则注册表（附录 A.6）与用户文案映射（前端 §6.2）同源导出。
- 变更通知范围纯函数：`scope ∩ (calendar.event_types ∪ rule_ids 所涉事件类型)`。
- 日历有效节点纯函数：`基础可见节点 ∪ 提醒规则所需节点`，标注哪些是"提醒关联节点"及引入它的规则 ID。

**关键约束**

- 这些函数 Worker 与 Web **共用同一份实现**，前端不得另写判断、不得按中文标签反推规则（前端 §12.1）。
- 提醒发送资格**不得**与 `calendar.node_types` 隐式相交。
- 用户文案是映射，不是第二份业务定义。

**不在范围**：存储、API、投影到 ICS 的字符串生成。

### P1-03 · 参数注册表与附录 A.5 等式校验

| 项 | 内容 |
| --- | --- |
| 前置 | P1-02 |
| 允许改动范围 | `packages/contracts/src/params/**`、`scripts/params/**` |
| 继承合同 | 附录 A 全表、A.5 等式；`CONTRACTS_BASELINE.md` §11 |
| 验收 ID | A-P1-PARAM |

**交付物**

- 附录 A.1—A.5 的**全部参数**，使用与附录**完全一致的全大写名**，一行一参数，带含义注释与出处。
- `verifyParams()`：实现 `CONTRACTS_BASELINE.md` §11 的全部等式；任一不成立时抛出并**指明是哪一条**。
- `pnpm params:verify` 调用它，不成立时非零退出。
- Worker 启动路径调用它，不成立时**拒绝启动**。
- P0 待定项（`MODEL_MAX_INPUT`、`MODEL_MAX_BILLED_OUTPUT`、`SOURCE_LIMIT_PROFILE`）标记为未填写，并让依赖它们的能力**默认关闭**。
- 从注册表导出文档表格的脚本，保证文档与运行参数同源。

**关键约束**

- `DEFAULT_*` 必须在类型层面标注为**界面预选建议**，不得被服务端写入订阅行（§4.4、附录 A.1）。
- 不得使用斜杠缩写名、不得在消费方另起别名。
- `MAIL_BASE_MONTH` 那条等式含"本账单周期相交 UTC 日期数"，**账单周期不是自然月**，校验函数需要接收实际账单周期参数。

**反向验证（必须做）**：人为破坏任意一条等式，`params:verify` 必须失败并准确指出该条。

**不在范围**：预算账本的运行时逻辑（见 P1-07）。

### P1-04 · D1 schema、索引与迁移框架

| 项 | 内容 |
| --- | --- |
| 前置 | P1-02 |
| 允许改动范围 | `migrations/**`、`apps/worker/src/storage/**`、`scripts/migrate/**` |
| 继承合同 | §8.1 逻辑数据契约全表 |
| 验收 ID | A-P1-DB |

**交付物**

- 按 §8.1 的十四个数据组建立表与约束。必须出现的字段不得遗漏，包括：
  - `sessions`：`absolute_expires_at`（**含抖动，创建时固定**）、`expires_at`、`renewed_at`、`label`、auth/恢复 epoch。
  - `user_subscriptions`：`state`、`revision`、`interest_enabled_at`。
  - `email_channels`：`enabled`、`routine_enabled`、租期、`last_renewed_reason`、`channel_revision`。
  - `calendar_feeds`：`namespace`、`view_revision`、`token_hash`/`token_ciphertext`、`token_generation`、`last_feed_poll_at`、**`last_served_node_count`、`last_served_view_revision`、`last_served_generation`**（缩水守卫用）。
  - `deliveries`：`dedupe_family`、`priority`、`mail_outbox_ref`；`mail_outbox` 一条可对应多条 Delivery。
  - `usage_periods`：预算池、周期、`reserved`/`settled`/`uncertain`、**`envelope`、`carry`**；`dispatch_cursors` 按池保存；`activity_write_failures`。
  - `recovery_credentials`：`generation`、`consumed`、`saved_confirmed_at`。
- 索引覆盖 §8.1 末段列出的全部访问路径。
- `pnpm migrate:check`：空库顺序重放全部迁移 → 校验 schema 与索引；输出真实 `rows_read` 的基准查询报告。

**关键约束**

- **禁止**建立 `feed_retirements`、私人撤销池、筛选差集暂存、逐用户取消记录、全局 `calendar_change_no`。
- `email_key` 唯一；实际投递地址不可由普通登录请求改写。
- 迁移只进不退；破坏性变更需 ADR。
- 不得把位图过滤假定为天然命中普通索引——先缩小状态/区域范围再做有限匹配。

**不在范围**：业务读写逻辑。

### P1-05 · 条件提交（CAS）原语与并发测试

| 项 | 内容 |
| --- | --- |
| 前置 | P1-04 |
| 允许改动范围 | `apps/worker/src/storage/**`、`tests/contract/**` |
| 继承合同 | §3.6、§8.1 末段、[R08] |
| 验收 ID | A-P1-CAS |

**交付物**

- 统一的条件提交原语：一组相关写入**要么一起成立、要么一起失败**，由统一条件守卫或数据库约束保证。
- 容量预占/释放原语：**禁止 `COUNT` 后无条件 `INSERT`**。
- 测试（在真实 D1 上跑）：
  - **CAS 更新零行时后续写入不生效**（这是 D1 `batch` 不会自动帮你做的事）。
  - 数据库报错 与 条件未命中 **分别**有用例。
  - 并发注册预占、并发挑战消费、并发会话激活、并发配置 CAS 各一组真实并发用例。

**关键约束**

- `batch` 的 SQL 失败回滚 ≠ CAS 零行自动失败（§3.6）。这一条必须有一个会在错误实现下失败的回归测试。

**不在范围**：具体业务的调用方。

### P1-06 · 密钥用途隔离、字段加密与 MAC 原语

| 项 | 内容 |
| --- | --- |
| 前置 | P1-03 |
| 允许改动范围 | `apps/worker/src/storage/crypto/**`、`packages/contracts/src/crypto-types/**` |
| 继承合同 | §4.1、§4.3、§6.1、§7.6、§8.3 |
| 验收 ID | A-P1-CRYPTO |

**交付物**

- 按用途隔离的密钥句柄：OTP MAC（独立 pepper）、邮箱 lookup HMAC、字段加密、退订 MAC（带 `key_id`）、CSRF、VAPID、管理员、恢复 epoch。用途混用在类型层面不可能。
- 认证加密：唯一 nonce，认证数据包含**记录类型与 ID**。
- 明确的两类存储策略：
  - **只存 hash/MAC**：会话 token、恢复码、Feed token 校验值。
  - **受控密文（有明确理由的例外）**：短期 OTP 发信载荷、`AUTH_COMPLETION_TTL` 内的完成回执、Feed token 供所有者再次复制的密文。
- `SECRET_BITS = 256` 的随机生成器；验证码另按 `OTP_DIGITS` 均匀随机生成。
- 日志脱敏白名单与一个"禁止字段"清单的自动检查。

**关键约束**

- 验证码原值只存在短期加密发信载荷中，接受/消费/过期/终止后清除；**服务器能在发送阶段解密，因此不得宣传"不可读取"**（§4.3）。
- 完成回执必须严格到期清除，不保留长期可重放的登录结果。
- 退订 token 中**不得放邮箱明文**；不逐邮件存 token 行。

**不在范围**：认证流程本身。

### P1-07 · 限速与预算账本原语

| 项 | 内容 |
| --- | --- |
| 前置 | P1-03、P1-05 |
| 允许改动范围 | `apps/worker/src/storage/ledger/**`、`packages/contracts/src/budget/**` |
| 继承合同 | §9.1、§9.2、§9.5、[R16]；`CONTRACTS_BASELINE.md` §7 |
| 验收 ID | A-P1-BUDGET |

**交付物**

- 四个邮件池的账本：既有账号认证、新注册认证、基础业务、紧急业务。`settled + reserved + uncertain` 均占用可用预算。
- **基础池 envelope**（纯函数，L1 可测）：完整实现 `CONTRACTS_BASELINE.md` §7.1，含 `carry` 持久化与 `E=1` 兜底；被日硬上限截断的部分**留在 R 里、不进 carry**。
- **紧急池**：不做 envelope，直接按月池消耗；跌破 `MAIL_URGENT_FLOOR` 后收紧为只发取消/撤回。
- **认证池**：软线 `S = 剩余月额 / 剩余片段数`；超软线时同一规范邮箱当日第二次及以后降级为稍后重试并延长冷却；跌破 `MAIL_AUTH_FLOOR` 时只接受既有账号首次登录，暂停新注册发信与全部重发。
- 跨日/跨账单周期：任务未外发时**原子释放旧预留并按实际发送周期重新预占**；已调用或 unknown 的不释放。
- 月末半日作为独立片段。
- 近似边缘限速与精确数据库账本的分工：边缘只挡突发，配额与存量用账本（[R16]）。
- `USER_MUTATIONS_DAY` / `GLOBAL_MUTATIONS_DAY` 计数，且**不拦截终止路径**（退订、Feed 停用、会话撤销、紧急停用、删除）。

**关键约束**

- `R=20, D=25` 必须得到 `E=1` 而不是 0。这条写成显式回归测试。
- E 建立后不因每封发送重新计算而二次扣减；新增明确外部占用只减少后续可批准量，不抹掉已发生使用。
- UTC 日硬计数与每用户日限频**在账单月界不重置**。
- 应用账本不等于绝对账单封顶——平台按其真实接受时间计费，需留余量并对账。

**不在范围**：实际调度与发送。

### P1-08 · API 外壳：错误模型、Origin/CSRF、请求校验、日志脱敏

| 项 | 内容 |
| --- | --- |
| 前置 | P1-02、P1-06 |
| 允许改动范围 | `apps/worker/src/index.ts`、`apps/worker/src/shell/**`、`packages/contracts/src/errors/**` |
| 继承合同 | §8.2 末段、§8.3；前端 §11.3 |
| 验收 ID | A-P1-SHELL |

**交付物**

- 错误类型：`validation` / `unauthorized` / `conflict` / `rate_limited` / `capacity_reached` / `quota_paused` / `temporarily_unavailable`，形状在 contracts 定义一次。
- 认证存在性敏感结果的**折叠**机制：同一输入形状返回同一响应，不通过错误文案、时序或响应大小泄露。
- 写 API 统一中间件：JSON 校验、未知字段拒绝、尺寸上限（`API_BODY_MAX_BYTES`，认证另用小字段 schema）、Origin 校验、CSRF、所有权由服务端派生（**不接受请求体里的 user_id**）。
- CSP、no-referrer、严格同源 CORS；认证与退订页面不加载第三方脚本。
- 结构化日志与脱敏：Cookie、OTP、恢复码、完整邮箱、Feed/退订 URL、Push endpoint 与密钥不得出现；异常请求日志采样。
- 普通用户与管理员会话的权限域隔离骨架。

**关键约束**

- 能力型端点（退订、receipt、恢复、Feed）各执行自己的**窄**合同；**不因它们例外就放宽账号接口**（§8.2）。
- 个人 Feed **不得**放到交互登录墙后（§8.3）。

**不在范围**：具体路由的业务实现。
