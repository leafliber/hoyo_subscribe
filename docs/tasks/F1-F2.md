# F1 · 查询体验 ／ F2 · 订阅体验

> 依据：前端 v1.0 §2—§6、§8、§11、§12；主方案 §3.2—§3.3、§5、§6.3—§6.5。
> 这两轮可在**隔离原型环境**用标注为样例的数据推进，不等后端（前端 §14.2）。
> **但不得伪装权威结果**：样例预览标为样例，D2 缺口保持可见。

## 贯穿两轮的三条

1. **五类状态必须分开**（前端 §3.1）：公开数据 / 浏览筛选与界面偏好 / 编辑草稿 / 已保存订阅 / 接收方式与权限。**不得用一个 `subscribed` 或"同步成功"描述以上全部**。
2. **业务规则只消费 `packages/contracts`**，不在前端另设默认值、不按中文标签反推规则。
3. **不虚构尚未测量的指标**，不用效果图代替实现截图。

| 允许改动范围 | `apps/web/src/styles/**`、`apps/web/src/components/**`、`apps/web/src/pages/_*`、`tests/e2e/a11y.spec.ts` |
| 继承合同 | 前端 §2.1、§2.2、§11 |
| 验收 ID | U28 |

**交付物**

- **站名：HoYo日历**（所有者 2026-09-22 定案）。用于页头站点名与 `<title>` 后缀。
  合同文档只写了"站点名称"占位，此前 F1-01 用的"米哈游官方日程订阅"是推断值，已作废。
  站名只在一处定义（`_Layout.astro` 的 `siteName`），其余页面引用它，不各写一份。
- 主导航仅 **日程 / 我的订阅**；右上角登录入口或账号菜单；帮助与服务状态在页脚。
- 设计 token 单一文件（前端 §11.1 表）：字号 14/16/22/28px，间距 4/8/12/16/24/32px，内容宽度 1120px、单列表单 760px，断点 960px，触控目标 ≥44px，圆角 8px，基础色与状态色为语义变量。
- 可访问性基线：持续可见的标签（**不只用 placeholder**）、键盘可达、焦点明显、弹窗焦点移动与恢复、折叠区含错误时自动展开并定位、加载/保存/失败可被辅助技术获知。
- 路由骨架：`/`、`/events/{event_id}`、`/subscription`、`/login`、`/recover`、`/account`、`/help`、`/status`。

**关键约束**

- 浅色、低装饰、高信息清晰度；**不以大面积渐变、背景图、重阴影或大量卡片制造层次**。
- 颜色最终值写入**同一份 token 文件**，不同页面不得各选近似值。
- **关键结果不只依赖短暂 Toast**；减少非必要动效；倒计时不持续抢占读屏提示。
- 文字与背景对比度**通过测试检查**，未测试时不得宣称达到某个无障碍合规等级。
- 能力型 URL（Feed、退订、receipt）**不进入站内普通导航、公共缓存或偏好分享**。

**不在范围**：深色主题、月历格子、装饰动效（均非首版前置条件）。

### F1-02 · 日程首页

| 项 | 内容 |
| --- | --- |
| 前置 | F1-01（**G-D1′ 已定案，见下**） |
| 允许改动范围 | `apps/web/src/features/schedule/**`、`apps/web/src/pages/index.astro` |
| 继承合同 | 前端 §4 全节 |
| 验收 ID | U01、U03、U05、U06 |

**交付物**

- 骨架按前端 §4.1；默认**按时间排列的列表**，不是月历格子；首屏优先展示日程。
- 筛选：游戏有限多选；CN/简体中文直接标注**不做单选下拉**；"临近截止"快捷筛选；低频筛选折叠进"更多筛选"且**折叠后仍显示已选摘要**。
- **时间范围预设（D1′ 已定案，2026-09-22 所有者决定）**：

  全部档位按 **UTC+8 自然日对齐**，起点一律是**今日 00:00**（不是"此刻"），
  **含今天**并向后延伸：

  | 档位 | 窗口 | |
  | --- | --- | --- |
  | 今天 | `[今日 00:00, +1d)` | |
  | **近 3 天** | `[今日 00:00, +3d)` = 今天 + 未来 2 天 | **默认档** |
  | 近 7 天 | `[今日 00:00, +7d)` | |
  | 近 30 天 | `[今日 00:00, +30d)` | |
  | 未来 90 天 | `[今日 00:00, +90d)` | |
  | 全部 | 服务端窗口全量 | 受 `FEED_PAST_DAYS / FEED_FUTURE_DAYS` 约束 |

  日对齐而非"此刻起算"，是为了让"今天"这一档有确定语义，
  也避免同一档位在一天之内不断滑动导致条目忽隐忽现。

  **昨天带**：列表最下方固定附加一条"昨天"分组，`[昨日 00:00, 今日 00:00)`，
  **半透明呈现**。它不属于任何档位窗口，是常驻的回看出口
  （用户要确认"那个活动是不是已经结束了"）。排在最下方而非顶部，
  是为了不让已过去的内容占据首屏的黄金位置。

  这是**纯浏览态参数**：不进云端订阅、不等于 Feed 窗口、不随保存写入任何配置。
  档位定义放 `packages/contracts`（前端不得另写一套），但**与业务参数注册表分开**，
  标注为浏览态 UI 参数。

  ⚠ **半透明不得牺牲对比度。**前端 §11.2 要求文字与背景对比度通过测试检查。
  "半透明"是视觉降权手段，**不是降低可读性的许可**——实现时对合成后的实际颜色
  测对比度，不是对原色测。若达不到阈值，改用更小字号 / 更浅的分隔 / 折叠态，
  而不是继续降低不透明度。这条要在 F1-01 的 a11y 基线里就钉住。

  ⚠ 默认档只有 3 天，**空结果会是常态而非异常**（三款游戏在平静期很可能一条都没有）。
  前端 §4.5 要求的四种空态必须在 F1-02 就做对，不能留到 F1-04：
  "当前范围没有已发布日程" / "筛选没有匹配项" / "来源暂不可用" / "仍有待审核缺口"。
  其中第一种会是最高频状态，文案要给出口（如"试试近 7 天"），不能只留一行空白。
- 条目顺序：**时间 → 节点动作 → 活动名称 → 游戏 → 必要状态**。
- 排序：精确节点按时间，同时间用稳定身份确定性排序；**纯日期节点放"具体时刻未公布"区域，不伪造午夜参加精确排序**；未知日期放独立待定/变更区域，**不编造排序日期**。
- 时间与状态呈现严格按前端 §4.4 的八行表实现，含"本站撤回"与"官方取消"的区分。
- "近期重要变更"区块。
- 数据状态：来源核验时间 / 公告发布时间 / 发布代次时间**是不同字段**；四种空态分别表达（无已发布日程 / 筛选无匹配 / 来源暂不可用 / 有待审核缺口）。

**关键约束（红线）**

- **改浏览筛选不得修改已保存订阅**；只有用户主动点"将当前游戏选择用于订阅"才影响草稿，且**浏览时间范围等条件不随之隐式写入**。
- 可分享 URL **不得附带账号、草稿、日历地址或任何秘密**。
- 正文用"玩法结束""奖励领取截止""阶段解锁"等**具体动作**，不统一压成"截止"。
- 长标题换行，**完整时间和节点动作不得被省略号遮住**。
- 游戏标识用文字即可，**不依赖大图背景和品牌色区分内容**。
- 只显示倒计时而不给绝对时间 = 不合格。
- 未审核候选**不以事实条目展示**；只有聚合缺口信息可公开。
- 公共旧缓存可展示但**必须标明离线/陈旧及实际时间**；分页或加载失败保留已有条目并提供重试，**不显示为"全部加载完成"**。

### F1-03 · 事件详情

| 项 | 内容 |
| --- | --- |
| 前置 | F1-02 |
| 允许改动范围 | `apps/web/src/features/schedule/**`、`apps/web/src/pages/events/**` |
| 继承合同 | 前端 §5 |

**交付物**

- 固定顺序：**当前重要安排 → 完整节点时间线 → 变更说明 → 官方依据**。
- 时间线只呈现**实际存在**的节点；玩法结束与奖励截止分开，**不补齐不存在的节点**。

### F2-01 · 订阅页骨架与四类设置的语义分离

| 项 | 内容 |
| --- | --- |
| 前置 | F1-01 |
| 允许改动范围 | `apps/web/src/features/subscription/**`、`apps/web/src/pages/subscription.astro` |
| 继承合同 | 前端 §3.2、§6.1—§6.4；主方案 §5.1、§5.3 |
| 验收 ID | U09、U09a、U10 |

**交付物**

- 页面结构按前端 §6.1：① 关注的游戏 ② 提前提醒 ③ 日历显示 ④ 变更消息 ⑤ 实际日历预览；下方"接收方式"三个独立区域。
- 规则文案映射按前端 §6.2 表，从 contracts 同源导出；推荐项由 `DEFAULT_RULE_IDS` 决定，其余进"更多提醒"。
- 日历显示：`calendar.event_types/node_types`；折叠标题展示当前选择摘要，**不使用没有说明的"高级设置"**。
- 日历提醒开关对应 `calendar.alarms_enabled`，本身属于**待保存配置**。
- 变更消息四个开关单独分组，用一句话讲清范围：**日历里看得见的、或设了提醒的事件，出了变化就会通知**。

**关键约束（红线）**

- **规则可以一条都不选。**界面**不得**因此禁用变更消息开关；取消最后一条规则时只说明"将不再收到提前提醒，变更消息仍按所选游戏与日历显示范围发送"，**不制造连带关闭的确认步骤**。
- 变更消息**不依赖提醒规则**——折叠摘要不得写成"规则已配置"。
- 未启用 Feed 时可以配置 `alarms_enabled`，但只能显示"已选择日历提醒"，**不能显示"已在外部日历开启"**。
- 关闭日历提醒**不清空已选规则、不关闭邮件或 Push**；只移除提醒引入的额外节点和闹钟。
- 初始预选取 `DEFAULT_*`，**仍只是预选**；界面**不得把预选显示成"已保存"**。示例 JSON 永远不是默认值来源。
- 不提供每游戏一套配置、每通道不同提前量或自由输入分钟数。
- 当前主要任务只有一个主按钮；**通道管理不与内容保存合并**。保存栏可固定但**不得遮挡最后一项、焦点或错误提示**。

### F2-02 · 实际日历预览

| 项 | 内容 |
| --- | --- |
| 前置 | F2-01；正式预览需 **G-D2** |
| 允许改动范围 | `apps/web/src/features/subscription/preview/**` |
| 继承合同 | 前端 §6.5、§13.2；主方案 §5.2、§6.3 |
| 验收 ID | U07、U08、U21 |

**交付物**

- 预览遵守同一投影语义：`日历提醒关闭 → 基础可见节点`；`开启 → 基础可见节点 ∪ 当前提醒规则所需节点`；均受 scope、时间依据、窗口、更正与完整性约束。
- 以 Milestone 身份**去重**，不因基础筛选与提醒同时匹配而出现两条。
- 额外节点标注 **"提醒关联节点"**，并说明**由哪个规则引入**。
- 明确标记正在预览"未保存草稿"还是"已保存设置"，以及数据时间、窗口、是否完整。
- 新配置到来后**丢弃旧异步请求结果**，防止旧预览覆盖新草稿。

**关键约束（红线）**

- **事件类型被隐藏与节点类型被隐藏都要正确处理**，不能只处理"隐藏结束节点"这一种例子（U07 与 U08 是两个不同用例）。
- 纯日期、预计和未知节点**不能产生精确闹钟**。
- 取消、未知延期等更正条目**保留事实原因**，不以普通即将发生条目的样式展示。
- 样例预览**标为样例**；分页结果**不得声称全量**；实际 Feed 不得沿用界面分页而静默截断。
- 超限、缺数据或无法校验时**显示诊断，不伪造空日历**。
- D2 未关闭前，模拟预览**仅供体验验证，不充当正式启用证据**；不得让 UI 虚构"确认时所见永远等于稍后拉取结果"这种保证。
- 预览**不因查看而创建长期 Feed 或用户×事件状态**。

### F2-03 · 保存状态机与两设备冲突

| 项 | 内容 |
| --- | --- |
| 前置 | F2-01 |
| 允许改动范围 | `apps/web/src/features/subscription/save/**` |
| 继承合同 | 前端 §8.1、§8.2、§8.4；主方案 §5.4 |
| 验收 ID | U11、U16、U17 |

**交付物**

- 状态机：`已保存 → 本机修改 → 正在保存 → 已保存`，四个分支（字段错误 / 版本冲突 / 会话失效 / 结果不确定）。
- 显式"保存订阅"按钮；**不在每次勾选后调用写接口**；先规范化有限数组再判断有无实际变化，无变化不产生多余写请求。
- 每次请求保存独立的提交快照与 `expected_revision`；同一时间只发起一次保存；**请求后继续产生的新草稿不得被旧成功响应清空**。
- 结果不确定：保留提交快照与当前草稿，重新读取云端；一致则确认，不一致或已有后续修改则进入比较流程。**普通重试不跳过版本检查。**
- 409：停止自动保存，按游戏 / 提醒 / 日历显示 / 变更消息**分组**展示差异；两个选项"采用云端设置"与"保留草稿，返回编辑"。
- 成功文案：「云端设置已保存。若日历地址已启用，地址保持不变；外部日历的更新时间由客户端决定。」**日历关闭时不显示"地址保持不变"这类不适用句子。**

**关键约束（红线）**

- **不得把"强制覆盖"作为默认按钮或自动反复重试**；不默认自动合并。
- 开启或续订通道时展示其将使用的**已保存**配置摘要；有本机改动则先处理"保存后继续"或"使用已保存设置"，**不让用户以为尚未保存的规则已生效**。
- 关闭邮件、停用 Feed、撤销会话、紧急停用、删除**不被未保存草稿或普通修改额度挡住**；停用请求失败或结果未知时**不提前显示"已关闭"**。
- 续期 POST 的触发条件严格按主方案 §4.5：**只有显式状态变更或账号管理请求之后**；页面加载、路由切换、返回前台、预取、可见性事件、后台轮询、Service Worker **都不触发**（前端 §12.2）。

### F2-04 · 本机草稿、离线、导入与账号隔离

| 项 | 内容 |
| --- | --- |
| 前置 | F2-03 |
| 允许改动范围 | `apps/web/src/lib/storage/**`、`apps/web/src/features/subscription/draft/**` |
| 继承合同 | 前端 §8.3、§12.3；主方案 §5.4 |
| 验收 ID | U18、U19 |

**交付物**

- IndexedDB 草稿与允许的私人缓存**按 `user_id` 隔离**；游客使用独立空间。
- 离线：公开数据显示实际缓存时间；订阅改动标"仅保存在本机，尚未同步"；联网后提示有待保存草稿。
- 导入：先校验 → 生成**可比较草稿**；不覆盖云端。
- 偏好导出白名单：**不含邮箱、账号 ID、会话、恢复码、Feed/退订地址、Push 秘密、通道同意**。
- Service Worker **只缓存白名单公开资源**；私人 API、认证、退订和个人 Feed 不进其缓存。

**关键约束（红线）**

- **联网后不自动补提交，不自动开启任何通道，不触发权限弹窗。**
- 退出或换账号后清除当前内存视图；**旧请求结果不得写入新账号页面**；未重新确认对应身份时不展示其私人缓存。
- IndexedDB 的账号隔离**不等于加密存储**；会话、OTP、恢复秘密和能力 URL **不作为界面偏好落盘**。
- 账号必要数据导出是**另一项受认证操作**，不与可分享偏好混同。
