**不在范围**：深色主题、月历格子、装饰动效（均非首版前置条件）。

### F1-02 · 日程首页

| 项 | 内容 |
| --- | --- |
| 前置 | F1-01（**G-D1′ 已定案，见下**） |
| 允许改动范围 | `apps/web/src/features/schedule/**`、`apps/web/src/pages/index.astro` |
| 继承合同 | 前端 §4 全节 |
| 验收 ID | U01、U03、U05、U06 |

**交付物**

- 骨架按前端 §4.1；默认**按时间排列的列表**，不是月历格子；首屏优先展示日程。
- 筛选：游戏有限多选；CN/简体中文直接标注**不做单选下拉**；"临近截止"快捷筛选；低频筛选折叠进"更多筛选"且**折叠后仍显示已选摘要**。
- **时间范围预设（D1′ 已定案，2026-09-22 所有者决定）**：

  全部档位按 **UTC+8 自然日对齐**，起点一律是**今日 00:00**（不是"此刻"），
  **含今天**并向后延伸：

  | 档位 | 窗口 | |
  | --- | --- | --- |
  | 今天 | `[今日 00:00, +1d)` | |
  | **近 3 天** | `[今日 00:00, +3d)` = 今天 + 未来 2 天 | **默认档** |
  | 近 7 天 | `[今日 00:00, +7d)` | |
  | 近 30 天 | `[今日 00:00, +30d)` | |
  | 未来 90 天 | `[今日 00:00, +90d)` | |
  | 全部 | 服务端窗口全量 | 受 `FEED_PAST_DAYS / FEED_FUTURE_DAYS` 约束 |

  日对齐而非"此刻起算"，是为了让"今天"这一档有确定语义，
  也避免同一档位在一天之内不断滑动导致条目忽隐忽现。

  **昨天带**：列表最下方固定附加一条"昨天"分组，`[昨日 00:00, 今日 00:00)`，
  **半透明呈现**。它不属于任何档位窗口，是常驻的回看出口
  （用户要确认"那个活动是不是已经结束了"）。排在最下方而非顶部，
  是为了不让已过去的内容占据首屏的黄金位置。
  **（2026-10-05 ADR-0017 改为放在时间线顶部、默认折叠：所有者要求从上到下按时间先后。）**

  这是**纯浏览态参数**：不进云端订阅、不等于 Feed 窗口、不随保存写入任何配置。
  档位定义放 `packages/contracts`（前端不得另写一套），但**与业务参数注册表分开**，
  标注为浏览态 UI 参数。

  ⚠ **半透明不得牺牲对比度。**前端 §11.2 要求文字与背景对比度通过测试检查。
  "半透明"是视觉降权手段，**不是降低可读性的许可**——实现时对合成后的实际颜色
  测对比度，不是对原色测。若达不到阈值，改用更小字号 / 更浅的分隔 / 折叠态，
  而不是继续降低不透明度。这条要在 F1-01 的 a11y 基线里就钉住。

  ⚠ 默认档只有 3 天，**空结果会是常态而非异常**（三款游戏在平静期很可能一条都没有）。
  前端 §4.5 要求的四种空态必须在 F1-02 就做对，不能留到 F1-04：
  "当前范围没有已发布日程" / "筛选没有匹配项" / "来源暂不可用" / "仍有待审核缺口"。
  其中第一种会是最高频状态，文案要给出口（如"试试近 7 天"），不能只留一行空白。
- 条目顺序：**时间 → 节点动作 → 活动名称 → 游戏 → 必要状态**。
- 排序：精确节点按时间，同时间用稳定身份确定性排序；**纯日期节点放"具体时刻未公布"区域，不伪造午夜参加精确排序**；未知日期放独立待定/变更区域，**不编造排序日期**。
- 时间与状态呈现严格按前端 §4.4 的八行表实现，含"本站撤回"与"官方取消"的区分。
- "近期重要变更"区块。
- 数据状态：来源核验时间 / 公告发布时间 / 发布代次时间**是不同字段**；四种空态分别表达（无已发布日程 / 筛选无匹配 / 来源暂不可用 / 有待审核缺口）。

**关键约束（红线）**

- **改浏览筛选不得修改已保存订阅**；只有用户主动点"将当前游戏选择用于订阅"才影响草稿，且**浏览时间范围等条件不随之隐式写入**。
- 可分享 URL **不得附带账号、草稿、日历地址或任何秘密**。
- 正文用"玩法结束""奖励领取截止""阶段解锁"等**具体动作**，不统一压成"截止"。
- 长标题换行，**完整时间和节点动作不得被省略号遮住**。
- 游戏标识用文字即可，**不依赖大图背景和品牌色区分内容**。
- 只显示倒计时而不给绝对时间 = 不合格。
- 未审核候选**不以事实条目展示**；只有聚合缺口信息可公开。
- 公共旧缓存可展示但**必须标明离线/陈旧及实际时间**；分页或加载失败保留已有条目并提供重试，**不显示为"全部加载完成"**。

### F1-05 · F1-01 遗留修正：e2e 预览服务器与站名落实

| 项 | 内容 |
| --- | --- |
| 前置 | F1-02 |
| 允许改动范围 | `tests/e2e/playwright.config.ts`、`tests/e2e/*.spec.ts`（**仅站名相关断言**）、`apps/web/src/pages/_Layout.astro`（**仅 `siteName`**）、`scripts/e2e/**`（新建） |
| 继承合同 | 前端 §11；F1-01 卡「站名：HoYo日历」条款 |
| 验收 ID | A-F1-E2E、U28（复查） |

**为什么有这张卡（2026-09-27 验收发现）**

一、**e2e 的 `webServer` 启动机制有缺陷。**Astro 7.3.3 的 `astro preview`：

- 被 Playwright 拉起时**自行转入后台**（锁文件 `apps/web/.astro/preview.json` 记 `"background": true`，
  命令里并无 `--background`），前台以 0 退出 → Playwright 报 `Process from config.webServer exited early`；
- 项目内已有锁时**忽略 `--port`**，只报"已在运行"就退出；
- 请求端口被占时**悄悄换端口**（4173 → 4174 → 4175），而 Playwright 轮询的仍是 4173；
- 守护进程成为孤儿（PPID 1）无限期存活——验收时查出存活 5 天的孤儿。

实测：**无锁、空闲端口、`CI=true` 的干净条件下，3 轮仍有 1 轮 `exited early`。**
CI 目前是绿的，那是赢了竞态，不是配置正确；本机只要有残留守护进程就必挂。

还有一个隐患：`reuseExistingServer: !process.env.CI` 让本地运行**复用 4173 上已有的任何服务**——
如果那是另一个 worktree 起的旧构建，测试会静默地测错代码。

二、**站名仍是已作废的「米哈游官方日程订阅」。**旧名含"米哈游官方"，容易被读成官方站点，**部署前必须改掉**。

**交付物**

- `webServer.command` 换成**常驻前台**的静态服务器，直接服务 `apps/web/dist`，放在 `scripts/e2e/`。
  **零新增依赖**——Node 内置 `http` 即可，零依赖写法可参照 `scripts/probes/calendar-clients/serve.mjs`。
- **端口被占时快速、明确地失败**：打印占用信息并以非零退出，**不得换端口**。
- `reuseExistingServer` 改为 `false`：本地与 CI 同一语义，永远测本次构建。
- 静态服务对本站的行为与 `astro preview` 等价（路径到 `index.html` 的映射、404、MIME 类型），以现有 e2e 全部通过为准。
- `siteName = "HoYo日历"`，同步各 spec 中的站名断言。站名**只在 `_Layout.astro` 定义一处**。
- `apps/web` 的 `preview` 脚本保留给人手动预览，e2e 不再依赖它。

**关键约束**

- **不得用重试、加长超时、`--ignore-lock` 或"先 stop 再 start"掩盖问题。**`--ignore-lock` 不阻止转入后台，
  stop/start 仍是竞态。修的是机制，不是症状。
- 验收按三种状态逐一实测：(1) 完全干净——连续 5 轮全过、零 `exited early`；
  (2) 4173 被一个残留进程占着——**快速明确失败并指出占用者**，既不换端口也不复用；
  (3) 用例数与通过数与改动前一致（46 条：41 过、5 跳）。
- 除站名外不改任何业务测试的断言语义。
