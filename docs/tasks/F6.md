首版不带模型抽取（所有者 2026-09-30 决定）。规则模板覆盖不到的公告，P3-03 的规则路径会为它建一个 `uncertain` 的待审核候选，全靠人工审核。
P3-10 只做了 API；没有这个页面，所有者只能用命令行审核。上线前必须有。

**交付物**

1. **入口**：`/admin/`。不进普通导航，公共页面不链接它，页面带 `noindex`。
2. **登录：引导秘密换会话。**
   - 先 `POST /api/v2/auth/preauth` 取得 CSRF，再 `POST /api/v2/admin/session/bootstrap`，秘密只放在请求体里。
   - 输入框为密码类型，关闭自动填充；提交后立即清空。秘密不写 localStorage、sessionStorage，不进地址、日志和错误提示。
   - 失败统一提示"无法登录"；限速时显示可以公开的等待信息。
   - 是否已登录，以管理接口是否返回 401 为准，不在浏览器里另存登录状态。
   - Access 换会话不接（要所有者先配置 Access，见 `DEPLOYMENT_PREREQUISITES.md`）。
3. **待审队列**：`GET /api/v2/admin/review/queue`，按游标一路翻到底；显示创建时间、来源与文章。空队列明确显示"没有待审核的候选"。
4. **候选详情与操作**：
   - `GET /api/v2/admin/review/candidates/{id}`：并排显示保存的公告正文块、候选内容和逐条证据。正文、证据一律按文本渲染，不进 `innerHTML`。
   - 操作：新建（指定文章版本）、修正、驳回、批准、纠正、关联、撤回，各对应 P3-10 的一条路由。每个写操作都要填理由。
   - 候选内容首版用 JSON 文本框编辑 `proposal_json`；校验以服务端为准，前端不另写候选规则。
   - 每个写请求带上次读到的 `expected_updated_at`。409 时提示"已在别处改过"并重新读取，不自动覆盖。
   - 字段级 400 按字段显示（例如 `article_version_id: not_found`、`proposal_json` 过长）。
   - 批准、纠正、关联、撤回之后，**必须显示 `publication.outcome`**："已批准"不等于"已发布"。
     结果是"已批准、未发布"时给出"重试发布"：用最新的 `updated_at` 重发同一个操作。
5. **退出**（获准跨卡改 Worker）：P3-10 没有管理员退出接口。新增 `POST /api/v2/admin/session/logout`：
   - 需要管理员会话和绑定该会话的 CSRF；
   - 撤销当前管理员会话（写 `revoked_at`），清掉管理员会话 Cookie；重复退出也返回成功；
   - 用户会话不受影响。
   Worker 侧测试：退出后同一 Cookie 访问管理接口得 401；没有 CSRF 或拿用户会话调用都被拒绝。
6. **测试**（e2e 用拦截的接口响应，不连真实后端）：
   - 登录：秘密只出现在 bootstrap 的请求体里，提交后不留在输入框、地址和浏览器存储里；
   - 队列翻到底，空页也继续翻；
   - 正文与证据里的 `<img src=x onerror=...>` 之类内容只显示为文本，不执行；
   - 写操作带已读版本；409 不覆盖，提示后重新读取；
   - 批准返回"已批准、未发布"时如实显示，并能重试；
   - 字段级 400 显示在对应字段旁；
   - 退出后回到登录表单。

**关键约束（红线）**

- 管理员和用户会话互不替代：本页面不读写用户会话，也不调用 `/api/v2/me/*`。
- 不做"自动批准"或批量裁定；每个裁定都由人点击并填写理由。
- 不显示或记录引导秘密、Cookie 和 CSRF 的值。
- 构建期不注入任何管理员配置；页面本身不含秘密。

**已知限制（写进页面的帮助说明，本卡不改）**：管理员与用户共用同一个 CSRF Cookie 名（P3-10 复核记下的建议）。
在同一个浏览器里登录管理端，会顶掉用户页的 CSRF Cookie；用户页的写操作会被拒绝，直到它重新取得 CSRF。建议用单独的浏览器配置文件登录管理端。

**不在范围**：来源、预算、运行开关管理（P5-01）；Access 换会话；审计查询界面；批量操作。

认可的实现解释：
- 新建候选没有已有候选版本，现有 create schema 只收文章版本、候选 JSON 和理由；其余六种操作带已读 `expected_updated_at`。不要求给 create 添加不被 schema 接受的字段。
- 退出允许已撤销、未过期的原管理员凭证幂等重放。虽然路由采用窄入口的 public 外壳声明，仍须同源、绑定完整管理员 token 散列的 CSRF，并由 handler 核对已签发且未过期的管理员会话；用户凭证不能替代。普通 admin 鉴权继续拒绝已撤销会话，不扩大其他路由权限。
- `publication.outcome = unchanged` 明确“本次未发生新发布”，不声称从未发布；重试读取最新版，沿用原操作与理由，候选内容已变则停下。符合卡意。

必须改：
1. **退出成功必须有明确回执。**`features/admin/page.ts` 目前只等待 HTTP 成功就调用 `loggedOut()`。把退出响应拦截成 HTTP 200 `{}`，服务端会话仍保持有效，页面却显示“已退出管理端”。桌面/手机各一条独立探针均失败。须验证 `logged_out === true`；缺字段、false 或类型不符按未确认处理，不显示已退出。补标准 E2E，断言必须等待异步响应处理完毕；不能用点击后立即断言“不含成功文案”来虚假通过。不扩全站认证，不改后端幂等合同。
2. **队列创建时间固定为北京时间并标明。**当前 `new Date(row.created_at).toLocaleString("zh-CN")` 使用浏览器时区。设置 `America/Los_Angeles` 后，合成时刻 `1900000000000` 显示 `2030/3/17 10:46:40`，应显示北京时间 `2030/3/18 01:46:40`；页面也没有“北京时间”或“UTC+8”标注。桌面/手机的时间和标注四条探针均失败。按 `ENGINEERING.md` §5.1 固定展示时区，保留源毫秒事实，补非东八区浏览器测试。
