# 验收矩阵与测试映射

> 依据：主方案 §10.3（合并后的验收矩阵）、§10.4（分阶段放行）；前端 v1.0 §14.1（U01–U29）、§14.3。
> 验收方按本文件逐项复核。**未执行的测试写成通过 = 整张任务卡退回。**

## 1. 验收 ID 约定

- 后端/管线：`A-<阶段>-<域>`，例如 `A-P2-SESSION`。
- 前端：直接用前端文档的 `U01`…`U29`、`U09a` 等编号。
- 测试标题必须包含验收 ID，可被 `grep -r "A-P2-SESSION" --include="*.test.ts"` 找到（见 `ENGINEERING.md` §7）。

## 2. 证据的三个等级

| 等级 | 含义 | 可用于 |
| --- | --- | --- |
| **E1 自动化** | 仓库内测试，重跑可复现 | 绝大多数验收项 |
| **E2 受控观测** | 隔离环境的实际运行截图/日志，含时间与环境标识 | 前端交互、客户端行为、性能 |
| **E3 外部事实** | 真实账户、真实收件人、真实客户端、真实账单产生的证据 | 仅 P0 与 P5 的放行项 |

**E3 不能由 E1/E2 替代。**模拟登录、模拟已投递、模拟兼容性不得进入生产判定（前端 §14.3）。合成样本必须显式标记 `synthetic`，不得当作官方证据。

## 3. 后端与管线验收表

### P0（全部 E3；Agent 交付探测代码与登记模板，结论由所有者填写）

| 验收 ID | 必须取得的事实 |
| --- | --- |
| A-P0-PROBE | 探针只读、不开通资源；能报告目标环境对官方来源的可达性、D1 条件事务行为、DO 发送位置 |
| A-P0-SOURCE | 每个来源的真实样本；`source_id / game / region / adapter / approved_hosts / verified_publishers / cursor / poll_policy` 已登记；`SOURCE_LIMIT_PROFILE` 已填写 |
| A-P0-MODEL | 输入保护值、**完整计费输出上界**、可见 JSON 与计费输出的差异、推理相关 usage、截断率、修复率、延迟、单篇费用中位数与高分位 |
| A-P0-CAL | 至少一个客户端通过：完整快照删除 / 重新加入 / 改期 / VALARM；每个客户端单独记录版本、网络、操作与实测结果，**不共用一份"支持"结论** |
| A-P0-MAIL | 面向**普通收件人**（非 routing verified destination）的 messageId 与反馈 Queue 关联；`PLATFORM_MAIL_DAY_LIMIT` 实测值（账单周期与周期包含量在本项目不适用，见 ADR-0003） |
| A-P0-GATE | 结论表：每项通过/失败/未取得，失败项有明确决策（继续、降级、改方案） |

### P2

| 验收 ID | 必须覆盖的关键测试 |
| --- | --- |
| A-P2-PREAUTH | 检查顺序（结构 → 同源/CSRF → 限速 → Turnstile → 配额 → 原子预占 → 创建挑战）；关闭注册或满额时未知邮箱**不生成实际发信任务**且响应与普通申请同形；不回显"该邮箱不存在" |
| A-P2-OTP | 重发只旋转 generation，**不重置累计失败次数、不延长最初截止、不废掉其他浏览器挑战**；错误尝试持久扣减不被事务回滚抵消；`PREAUTH_MIN_TTL` 下限本身满足等式；preauth 临近到期再申请 |
| A-P2-CONSUME | 并发消费最多一次成功；不出现"会话已创建但挑战仍可用"；新账号以 `uninitialized` 建立且**不写入任何默认配置**；完成回执在 `AUTH_COMPLETION_TTL` 内、pending、原浏览器上下文匹配时可取，激活后立即清除 |
| A-P2-SESSION | 抖动后绝对期限**创建时固定**且不被续期突破；只有 §4.5 定义的真实前台操作触发续期（页面加载 / Feed 拉取 / 收邮件都不触发）；**pending 不挤 active**；名额满由用户选择撤销，不自动淘汰最早；集中注册队列被抖动摊平；会话列表含标签、`created_at`、`renewed_at` 及滞后说明 |
| A-P2-RECOVERY | **紧急停用后恢复码仍可用**且幂等；恢复登录消费后立即交付新码；保存确认前能力受限集合正确；`recovery_id` 单独提交无存在性差异；`RECOVERY_ATTEMPTS_HOUR/DAY` 生效 |
| A-P2-SUB | `uninitialized` 不参与匹配也不能开通道；首次合法保存转 `initialized` 且不可退回；非空约束只对 `initialized`；**规则为空 + 变更开关开启必须被接受**；两设备 409 不静默覆盖；无变化保存幂等；只有 ICS 语义变化才增 `view_revision` |
| A-P2-ACCOUNT | 换邮箱需"当前邮箱 OTP 或恢复码" + "新邮箱 OTP"；原子更新地址/`email_key`/`email_version`/`auth_epoch` 并撤销旧会话与待发任务；新邮箱业务邮件默认关闭；删除先原子标记 `deleting` 并增 `auth_epoch`；**Feed 停用/启用/重置只需有效会话 + CSRF + 确认 + 限速，不要求额外 OTP** |

## 5. 每阶段放行检查单

阶段全部任务卡通过后，逐项确认；**任何一项"待补"则阶段不算完成，下游门禁不开**。

- **P0**：A-P0-SOURCE / MODEL / CAL / MAIL 各有 E3 证据或明确的"失败 + 决策"；结论表已记录。
- **P1**：八张卡全绿；`params:verify` 能因人为破坏某条等式而失败（反向验证）；迁移可空库重放。
- **P2**：双设备、长会话与恢复码、保存冲突、退出与停用、**关闭注册不空发验证码** 五条纵向路径实跑通过。
