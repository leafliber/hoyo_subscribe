## 2. 门禁规则

门禁是**开始条件**，不是建议。前置未满足就开工的任务卡，交付时直接退回。

| 门禁 | 内容 | 阻断 |
| --- | --- | --- |
| G-P0-SOURCE | 每个来源已保存真实样本，并登记 `source_id / approved_hosts / verified_publishers / cursor / poll_policy` | P3-01、P3-02 |
| G-P0-MODEL | 已记录真实部署的输入保护值、**完整计费输出上界**、单篇费用分布、截断率与修复率 | P3-03 的模型路径（规则与人工路径不受阻） |

## 4. 并行策略

- **立即可并行**：P1-01…P1-04 与 F1-01；P0-01 与 P1 全部。
- **P1 完成后并行**：P2 纵向线 与 P3-01…P3-05 事实线（二者只在 P3-06 汇合）。
- **不要并行**：同一张卡拆给两个 Agent；P4-02 与 P4-04（预算与调度耦合过紧，串行更快）。
- **前端与后端**：F1、F2 用标注为样例的隔离数据推进，不等后端；F3 起必须对真实接口。

```text

不开通收费资源、不发真实邮件；不得命中 AGENTS.md 第 3 节禁止清单。
```

## 6. 阶段完成的判定

一个阶段"完成"当且仅当：该阶段全部任务卡的 PR 已验收通过，且 `docs/ACCEPTANCE.md` 中该阶段的放行检查单逐项有真实证据。**任何一项写"待补"的阶段都不算完成**，后续阶段的门禁不开。
