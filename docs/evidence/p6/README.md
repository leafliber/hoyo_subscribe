# P6-03 · Web Push 目标浏览器与网络取证清单

> 验收 ID：**A-P6-CLIENT**｜依据：主方案 §7.8 末段、§10.3；前端 §9.3；ADR-0025
> **每个"浏览器 × 设备 × 网络"单独一行结论，不共用一份"支持"表述。**未实测的格子写"未测"，不写"应该可以"。
> 状态（2026-10-06）：**尚无任何记录**。本文件只提供步骤与模板；真实客户端、真实网络与正式环境的取证由所有者执行（E2/E3）。

## 为什么单独取证

- 平台接受（推送服务返回 201）**不是**客户端存活或已显示的证明；只有浏览器显示通知并报回执才算收到。
- 不同浏览器走不同推送服务：Chrome、Samsung Internet、Opera 等走 Google（FCM，`fcm.googleapis.com`）；Firefox 走 Mozilla；Safari 与 iPhone/iPad 主屏幕应用走 Apple；Windows 上的 Edge 走 WNS。**中国大陆网络下 FCM 通常不可达**，这类浏览器可能收不到通知；结论必须按网络分别写。
- 未通过可以不开放 Push，但不得借此掩盖尚未验收的日历主通道（§7.8、P6-03 卡）。

## 前置

1. 已远端应用迁移 0029，已注入 `PUSH_VAPID_PRIVATE_JWK`（`DEPLOYMENT_PREREQUISITES.md` §1），网页与 Worker 已部署。
2. 运行开关：外发总闸开、只读关；**`push_enabled` 只在取证窗口内打开**，取证结束按所有者决定保留或关闭。
3. 测试账号：已保存订阅、已确认恢复码。建议订阅里只开一个游戏，减少业务通知量。
4. 每条记录写明日期时间（北京时间）、正式站点提交（版本 tag）、浏览器与系统版本、网络（运营商 / 是否经代理）。不贴 endpoint、receipt token、截图里的私人信息。

## 每个组合的步骤

| 步骤 | 操作 | 要观察什么 / 记录什么 |
| --- | --- | --- |
| 1 | 打开「我的订阅」，确认「浏览器通知」卡片出现，**点击前**没有任何权限弹窗 | 点击前无弹窗；卡片显示"尚未授权" |
| 2 | 点「在当前浏览器开启通知」并允许 | 系统是否弹出"HoYo日历 · 浏览器通知验证"；卡片从"验证中"变为"本浏览器接收验证通过"所需时间 |
| 3 | 若 2 分钟内没收到：等冷却后点「重新发送验证通知」 | 第几次收到；最终是否在激活期限内通过（未通过记"激活失败"） |
| 4 | 点「发送测试通知」 | 是否弹出；卡片"最近测试"是否出现"本浏览器已收到" |
| 5 | 关闭浏览器（手机锁屏）后，在另一台设备的账号页对这台浏览器点「发送测试通知」 | 浏览器未打开时能否收到（Android/iOS 尤其重要） |
| 6 | 等一条真实业务通知（或在测试环境构造一个即将到期的提醒） | 是否收到；点击通知是否打开本站对应活动详情 |
| 7 | 点「暂停本浏览器通知」，再触发测试 | 暂停后不应再收到；恢复需要重新验证 |
| 8 | 在浏览器设置里撤销本站通知权限，再从账号页触发测试 | 推送服务返回什么（404/410 时绑定应变为"已失效"）；页面如实显示 |
| 9 | 检查运行开关页 `push_enabled` 仍为开 | 若被自动关闭：说明推送服务返回了 401/403，先核对 VAPID 配置，不要直接重开 |

## 结论怎么用

- 只对实测通过的组合在帮助页或界面里称"可用"；未测、失败的组合不外推。
- 任何组合失败都不影响日历与邮件的验收与开放。
- 取证中发现 `push_enabled` 被自动关闭、或大量绑定变为"已失效"，先停止取证并记录，交给维护者核对配置。
