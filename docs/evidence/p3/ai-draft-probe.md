# P3-17 AI 草稿真实调用取证（2026-10-04）

> 用途：确认 Workers AI 对 `@cf/qwen/qwen3-30b-a3b-fp8` 的真实响应形状、`/no_think` 是否生效、计费口径，并据此定提示词与服务端核对规则。
> 这是 ADR-0009 的依据之一，**不是** P0-03b 的质量评估（样本只有 5 篇，不能外推召回率）。

## 方式

- 时间：2026-10-04（UTC）。经所有者已授权的 Cloudflare 连接器调用 `POST /accounts/{id}/ai/run/@cf/qwen/qwen3-30b-a3b-fp8`，共 6 次。账户 ID 留源码外。
- 调用前确认：账户当天与最近 7 天的 Workers AI 用量都是 0（GraphQL `aiInferenceAdaptiveGroups`）。
- 输入：仓库 `fixtures/` 里的真实官方公告，用本卡的 `readableBlockText` 与 `draftMessages` 生成提示词（第 4、5 次用的是收紧后的提示词 v1）。参数：`max_tokens` 3000，temperature 0.2。
- 没有把模型输出写进任何生产数据；测试用的固定响应取自第 1、4 次的模型输出。

## 结论

1. **响应形状**：OpenAI 风格，`choices[0].message.content` 是 JSON 文本，另有 `response`（已解析的对象）与 `usage`。`usage` 带 `prompt_tokens`、`completion_tokens`、`neurons`。
2. **计费口径**：平台回报的 `neurons` 与 4,625 / 30,475 Neurons 每百万输入/输出 token 的计算结果逐位一致（例如 1219×4625/10⁶ + 221×30475/10⁶ = 12.372）。
3. **思考输出**：`/no_think` 生效，`reasoning_content` 只有两个换行，输出 token 就是可见 JSON。账本仍按 `max_tokens` 3,000 预占，不依赖这一点。
4. **服务端必须逐字核对**：第 2、4 次说明，模型会推算或挪用时间。草稿只保留所引块里逐字存在的时间文本，其余丢弃并告诉审核员；草稿永远要人工批准。
5. **输入规模**：典型活动/卡池公告的提示词约 4.5 KB、1,200–1,400 token。24,000 字节的输入上限覆盖除版本更新说明（30–57 KB 原始 HTML）以外的公告，超限的公告记为"跳过"，交人工处理。（ADR-0010 起输入上限改为 64,000 字节，版本公告也纳入起草；现行数值以 contracts `AI_DRAFT_PROFILE` 为准。）
